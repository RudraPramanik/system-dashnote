Retrieval-Augmented Generation

Full field guide to RAG: embeddings, chunking, indexing, vector search, hybrid + rerank, and agentic retrieval — mapped onto what DashNote already ships and what to build next.

01 What is RAG shipped

RAG grounds an LLM in your documents at query time — retrieve first, then generate — so answers cite real notes instead of inventing them.

Without RAG

  • Model only knows training data
  • Hallucinates workspace facts
  • No citations to your notes

With RAG

  • Fetch relevant chunks from Qdrant
  • Stuff them into the prompt
  • Answer + grounded citations
user question→ retrieve→ budget context→ LLM→ answer + citations
DashNote
Fast path: POST /ai/chat → RagService.answer(). Agent path: POST /ai/agent tools call the same service. Never replace chat with agent — they coexist.

03 Embeddings shipped

An embedding maps text → a dense vector so “similar meaning” becomes “nearby points” in high-dimensional space.

Dense

Semantic meaning. DashNote’s path.

Sparse

BM25 / SPLADE — keyword precision.

Multi-vector

ColBERT-style late interaction.

Properties that matter

  • Dimension — must match collection (DashNote: 3072)
  • Same model for index and query — never mix families
  • Batching + cache — cut cost and latency on re-embeds
DashNote settings
EMBEDDING_MODEL=gemini/gemini-embedding-2 · EMBEDDING_DIMENSION=3072 · Redis cache embed:v1:{sha256(text)} · retries in ai/embeddings/litellm_provider.py

05 Indexing shipped

Indexing writes vectors + payload into the vector DB so search can filter and score later.

Write pattern

06 Vector database Qdrant

A vector DB stores embeddings and runs approximate nearest-neighbor (ANN) search with metadata filters.

  • Postgres + pgvector works at small scale; dedicated VDBs shine with filters + HNSW
  • Payload filters (tenant, RBAC) applied during search, not after
  • Collections isolate schemas (notes vs files)

Exact cosine over all points — O(n), correct, slow.

ANN (HNSW) — approximate top-k, sublinear, good enough for RAG.

Trade recall for latency. For RAG, high recall on top-20 + rerank beats exact top-5 of a weak embedding.

  • Collections: notes_chunks, files_chunks
  • Distance: cosine · dim 3072
  • Client singleton in ai/retrieval/client.py
  • Search only via WorkspaceVectorSearch — never raw client in routers

    08 Hybrid search not yet

    Combine dense (semantic) and sparse (keyword) signals so paraphrases and exact tokens hit.

    Dense wins

    • “deadline for Q3 plan” ≈ roadmap note
    • Synonyms & paraphrases

    Sparse wins

    • Codes: INV-2048
    • Error strings, rare names

    Fusion

    • RRF (Reciprocal Rank Fusion) — rank-based, scale-free, usually best first try
    • Weighted sum — needs score calibration
    • Qdrant prefetch + fusion — dense + sparse in one query API

      Today WorkspaceVectorSearch is dense-only (comment says “hybrid-ready”). Next step: BM25 or sparse vectors + RRF inside the wrapper — keep RBAC filter on both branches.

      09 Reranking not yet

      Retrieve broad (top 20–50), then score query–document pairs with a cross-encoder and keep top 5 for the LLM.

      ANN top-30→ cross-encoder→ top-5 context

      Why

      Bi-encoders are fast but shallow. Cross-encoders see full query+chunk together.

      Cost

      Latency + GPU/API. Only score a shortlist — never the whole corpus.

      • Cohere / Voyage / Jina rerank API
      • Local bge-reranker in worker sidecar
      • LLM-as-reranker (slow, expensive — last resort)

      Place after fusion, before TOKEN_BUDGET_PER_REQUEST truncation in RagService.

      • Reranker unavailable → fall back to dense order (fail-open)
      • Never drop RBAC filter to “improve” recall
      • Don’t send private chunks to a third-party reranker without a DPA

      10 Agentic RAG partial

      Classic RAG: one retrieve → one generate. Agentic RAG: the model decides when/how to retrieve (and may loop, rewrite, or use tools).

      q→ retrieve→ generate

      DashNote: /ai/chat* — low latency, fixed pipeline, citations in metadata.

      q→ agent→ search_notes→ maybe tools again→ answer

      DashNote: LangGraph /ai/agent* with search_notes, summarize_workspace, create/update note.

      • Tool-calling RAG — model invokes search (✓ you have this)
      • Self-RAG / CRAG — critique retrieval, re-query if weak
      • Multi-hop — answer needs several notes chained
      • Router — send simple Q to chat, complex to agent
      Architecture law
      Agent tools call RagService.answer(...) with plain strings — never RequestContext. Mutations go through NoteService, not repositories.

      11 Context budget & citations shipped

      Retrieval quality dies if you dump too much text or trust the model’s chunk IDs blindly.

      Budget

      TOKEN_BUDGET_PER_REQUEST=8000 chars shared with thread history via ContextBuilder.

      Citations

      Ground against retrieved set server-side. SSE: citations only in final metadata event.

      Also worth knowing

      • Lost-in-the-middle — put best chunks first/last, not only middle
      • Dedup — same note, many chunks → diversify before budget cut
      • Structured prompt — clear “CONTEXT FROM YOUR NOTES” boundary (injection defense)

      12 Query rewriting not yet

      Users ask poorly. Rewrite / expand the query before embedding to boost recall.

      HyDE

      Generate a fake answer, embed that.

      Multi-query

      3 paraphrases → union results.

      History rewrite

      Resolve “that note” using thread.

      Gap
      DashNote embeds the raw user message. Thread history is in the generation budget, not used to rewrite the retrieval query. Good next slice for multi-turn chat.

      15 Implement in DashNote

      Concrete upgrade order that respects import laws and RBAC.

      1. Hybrid inside WorkspaceVectorSearch

        Add sparse path (Postgres full-text on note content, or Qdrant sparse vectors). Fuse with RRF. Apply build_rbac_filter to both branches. Keep routers calling the same wrapper — zero API change.

      2. Rerank shortlist in RagService

        After search, before budget: rerank(query, chunks) → top_n. Setting RERANK_ENABLED / provider. Fail-open to dense order. Do not put rerank in routers.

      3. Conversational query rewrite

        In chat with thread_id, rewrite retrieval query from last N messages before embed. Keep rewrite LLM call short; fall back to raw message on failure.

      4. Unified notes + files retrieve

        Search both collections (or multi-query), tag source type in payload, merge ranks. Agent search_notes may become search_workspace.

      5. Eval set + CI gate

        30–50 labeled (query → note_id) pairs. Script hits test-search / RagService; fail PR if Recall@5 drops. Store in tests/ai/fixtures/rag_eval.json.

      Minimal hybrid sketch

      # ai/retrieval/wrapper.py (conceptual)
dense = await qdrant.query_points(... dense ..., query_filter=rbac)
sparse = await sparse_search(... same rbac ...)
fused = rrf([dense, sparse], k=60)[:limit]
return [to_search_result(p) for p in fused]

      workspace_id only from JWT · search only via wrapper · writes only via indexer · RagService takes plain strings · append-only settings / compose / requirements.
