00 Single-agent baseline DashNote today

One LLM + tools in a loop is already an agent. Multi-agent patterns are optional complexity — only add them when a single agent’s tool set or context gets too crowded.

START → agent → tools? → agent → END 
# ai/workflows/workspace_assistant.py
START → agent → (tools | end | limit) → tools → agent → …

Tools: search_notes · create_note · update_note · summarize_workspace
State: messages + workspace_id + user_id + role + steps_taken + thread_id
HTTP:  POST /ai/agent · POST /ai/agent/stream
Law:   /ai/chat* stays the fast non-agent RAG path
When to stay single-agent
One domain (notes), <10 tools, shared tenant context, one user goal per turn. That is DashNote’s current sweet spot — don’t multi-agent for fashion.

01 Sub-agent not yet

A sub-agent is a nested specialist invoked by a parent agent (often as a tool). Parent keeps orchestration; child owns a narrow skill and returns a result.

Parent

  • Owns user conversation
  • Decides when to delegate
  • Merges child output into answer
  • Holds tenant identity

Sub-agent

  • Narrow prompt + tools
  • Fresh or scoped context
  • Own step budget
  • Returns structured summary
  • Isolate long research so parent context stays clean
  • Different model / temperature per skill
  • Independent max_iterations for expensive loops
  • Clear ownership: “research agent” vs “mutate agent”

A tool is one function call. A sub-agent is a mini graph (model ↔ tools) that may take many steps, then returns one payload to the parent.

Today search_notes / summarize_workspace are tools calling RagService — not nested agents. First sub-agent candidate: a retrieval specialist that may rewrite queries + multi-hop search, returning a grounded brief to the parent.

02 Multi-agent systems not yet

Several agents with distinct roles coordinate on a task. Patterns differ by who decides the next speaker.

Supervisor

Router picks specialist. Clear control. Good default for products.

Swarm / peer

Agents talk or hand off freely. Flexible; harder to bound cost.

Pipeline

Fixed stages (research → draft → review). Predictable latency.

03 Agent handoff not yet

A handoff transfers control (and usually a summarized state) from agent A to agent B. Unlike a sub-agent call, A may not resume — B owns the user turn.

Handoff package

  • Goal / remaining work
  • Facts already established
  • Open questions
  • Tenant ids (immutable)
  • Allowed tools for B

vs tool return

  • Tool return → parent continues
  • Handoff → active agent switches
  • Need clear UI: who is speaking
  • Checkpointer may store active_agent
# Conceptual LangGraph state extension

04 Agent harness mostly shipped

The harness is everything around the model that makes agents safe and operable: loop, tools, memory, limits, streaming, observability, evals.

Harness piecePurposeDashNote
Graph + ToolNode Model ↔ tools loop done workspace_assistant.py
Typed state Tenant + steps done AgentState
Step guard Stop infinite loops done AGENT_MAX_ITERATIONS=10
Tool timeout Bound hung tools done AGENT_TOOL_TIMEOUT=30
Checkpointer Resume / thread state done Postgres AsyncPostgresSaver
Product threads User-visible history done AIThread + thread_id bridge
HTTP + SSE Invoke & observe done /ai/agent*
LLM retry Transient failures done acompletion_with_retry → 503
RBAC tools Safe side effects done services only
Trajectory evals Quality gate todo ship-plan agent goldens
Human approval node Gate mutations partial prompt policy; no interrupt UI yet
Tools → services only · plain workspace_id/user_id/role · LiteLLM OpenAI tool defs (not bind_tools) · lazy compile() · checkpointer ≠ SQLAlchemy pool · never replace /ai/chat*.
SSE: token, tool_start, tool_end, done, [DONE] via graph.astream_events — the harness’s real-time window into the loop.

05 Autonomy levels levels 0–2 live

How much the system may act without a human in the loop. Raise autonomy only with harness + evals + governance.

LevelMeaningDashNote analogue
L0 Answer only; no tools /ai/chat* RAG
L1 Tools on explicit ask Agent prompt: create/update only if asked
L2 Bounded auto actions Worker tags/metadata (additive); embed upsert
L3 Propose destructive; human gate AutomationDecisionEngine hold path
L4 Unattended high-impact Not desired for core product
Product choice
Users pick L0 (/ai/chat) vs L1–L2 (/ai/agent). Destructive automation stays fail-safe blocked unless confidence ≥ 0.95 and non-destructive.
