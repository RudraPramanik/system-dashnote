02 Why streaming matters

Wall-clock latency may be identical to a buffered response. Perceived latency is not.

TTFT — time to first token

First visible character is the “app is alive” signal. Retrieval + LLM cold start dominate; stream so the user sees progress as soon as generation starts.

Perceived latency

A 4s blank spinner feels broken. The same 4s with tokens after 600ms feels responsive — even if total time is unchanged.

Trust

Progressive text + a clear “Sources” reveal after metadata tells users the answer is grounded, not invented mid-typewriter.

Control

Streaming enables Stop. Without a live connection, interrupt is fake — the model keeps burning tokens server-side.

MetricWhat users feelProduct target
TTFT Blank bubble vs first words Skeleton → first token ASAP
Tokens / s Typing pace Smooth append; avoid burst then stall
Time to citations “Where did this come from?” Reveal on metadata, not mid-token
Cancel latency Did Stop work? Abort client + drop connection

03 Transport — SSE vs WebSocket vs chunked HTTP

DashNote chat uses Server-Sent Events over POST /ai/chat/stream. Pick transport by directionality and ops simplicity — not fashion.

One-way server → client event stream on a long-lived HTTP response. Perfect for token deltas, tool progress, and a final metadata packet. Auth stays on the initial POST (Bearer). Proxies understand HTTP.

  • DashNote: media_type="text/event-stream"
  • Frames: data: {json}\n\n then data: [DONE]\n\n
  • Headers: Cache-Control: no-cache, X-Accel-Buffering: no

Full duplex. Useful when the client must send frequent mid-session control messages on the same socket (collaborative editors, voice). Heavier ops: sticky sessions, upgrade paths, custom reconnect.

Overkill for “ask once, stream answer, optional cancel via disconnect.”

Raw chunked transfer without an event framing convention. Works, but clients reinvent parsers. SSE is chunked HTTP with a boring, shared contract.

Nginx / CDN
Without X-Accel-Buffering: no and Cache-Control: no-cache, the proxy may hold tokens until the generator finishes — streaming becomes a fake “wait then dump.” 
return StreamingResponse(
    generate(),
    media_type="text/event-stream",
    headers={
        "Cache-Control": "no-cache",
        "X-Accel-Buffering": "no",
        "Connection": "keep-alive",
        "Transfer-Encoding": "chunked",
    },
)

05 Partial tool calls & agent streaming

Chat SSE is answer-shaped. Agent SSE (POST /ai/agent/stream) is trajectory-shaped — tokens interleaved with tool lifecycle events.

token→ tool_start→ tool_end→ token→ done→ [DONE]
EventMeaningUI pattern
token Assistant reasoning / final prose Same typewriter as chat
tool_start Tool name + args Chip: “Searching notes…”
tool_end Result summary Expandable step; never invent success
done thread_id, steps_taken Collapse steps; enable follow-up
Partial tool-call args
Some providers stream tool-call JSON argument fragments. Buffer until the tool call is complete before rendering args as truth — show “Preparing tool…” until tool_start / complete args arrive. DashNote agent stream emits discrete start/end from LangGraph astream_events.

06 Abort · interrupt · cancel NOT YET UX

Stop must tear down the client read and the HTTP connection. Cosmetic “Stopped” labels without abort leave the LLM generating.

AbortController (fetch)

const ac = new AbortController();
fetch("/ai/chat/stream", {
  method: "POST",
  signal: ac.signal,
  headers: { Authorization: `Bearer ${t}`,
             "Content-Type": "application/json" },
  body: JSON.stringify(body),
});
// Stop button:
ac.abort();

Disconnect effects

  • Client: stop appending; keep or discard partial
  • Server: generator cancelled when response closes
  • UX: “Generation stopped” + keep draft text
  • Do not auto-retry after user abort
EventSource caveat
Classic EventSource is GET-only and awkward with Bearer auth. DashNote’s POST SSE is consumed with fetch + ReadableStream (or a small SSE parser). Abort maps cleanly to signal.

07 Product UX patterns

The stream is the animation system. Design states around phases, not a single spinner.

Skeleton / retrieving

Between Send and first token: shimmer lines or “Searching your notes…”. Retrieval can take hundreds of ms before TTFT.

Cursor / typewriter

Blinking caret while tokens arrive. Remove on [DONE] or abort. Prefer monospace-friendly markdown render that updates in place.

Citation reveal

Placeholder “Sources loading…” optional; real chips only after metadata. Animate open — never invent titles early.

Optimistic placeholders

Insert empty assistant bubble immediately on Send. Replace skeleton with streamed text. Rollback bubble on hard error if no tokens arrived.

Phase machine

idle → sending → retrieving → streaming → citing → done
                  ↘ error        ↘ aborted

08 Long-running jobs vs chat stream

Chat SSE is for seconds-scale generation. Embed / index / automation jobs are minutes-scale — different product surface.

Chat / agent streamWorker job
Lifetime Seconds · one HTTP response Tens of seconds → minutes
Transport SSE on the request Enqueue → poll / progress events / webhook
DashNote /ai/chat/stream, /ai/agent/stream ARQ workers (embed, summarize, tags)
UX Typewriter + Stop Progress bar, toast, refresh metadata
Anti-pattern
Do not hold an SSE chat connection open for file indexing. Return a job id; stream progress separately (or poll). Mixing them couples UI timeouts to batch work.

09 Failure UX

Mid-stream errors must be visible. Silent truncation is a hallucination of completeness.

  • Server yields {"type":"error","message":"…"} then [DONE]
  • UI: banner under partial answer — “Stream failed. Partial reply kept.”
  • Do not show citations if metadata never arrived
  • 429 / 503 before body: map to friendly copy (rate limit / LLM down)
  • Retry only idempotent “no tokens yet” failures
  • After N tokens, prefer “Regenerate” (new request) over silent reconnect
  • Never auto-retry after user abort
  • Backoff + jitter if you do auto-retry on network blips
  • SSE over POST rarely resumes mid-token — treat reconnect as new turn
  • Optional: resume thread from last persisted assistant message
  • Show “Connection lost” rather than infinite spinner
