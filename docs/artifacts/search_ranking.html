Hybrid search & reranking

Short field guide: when vectors miss keywords, how hybrid + rerank fix it, and how to add both to DashNote without breaking RBAC or import laws.

01 Why hybrid?

Pure semantic search is great at meaning — weak at exact IDs, names, and rare terms.

Dense (vectors) wins

  • “deadline for Q3 plan” ≈ roadmap note
  • Paraphrases & synonyms

Sparse (keywords) wins

  • Exact codes: INV-2048
  • Names, error strings, file titles
Rule of thumb
Hybrid = retrieve with both signals, then (optionally) rerank the shortlist. DashNote today is dense-only — hybrid is the natural upgrade.

02 Dense · sparse · hybrid

Three retrieval modes — know what each stores and scores.

Embed query + chunks → cosine / dot similarity in a vector DB.

DashNote: Gemini embed → Qdrant notes_chunks / files_chunks, dim 3072, via WorkspaceVectorSearch.

Inverted index / BM25 / keyword match on text (or sparse vectors like SPLADE).

Strong on exact tokens. Weak when the user paraphrases.

Run both → merge (RRF or weighted sum) → top-k for the LLM.

query→ dense top-N+ sparse top-N→ fuse→ top-k
FusionIdeaNote
RRFScore by rank: 1/(k+rank)Simple, no score calibration
Weightedα·dense + (1−α)·sparseNeeds comparable scores
Qdrant hybridNative dense+sparse queryGood fit if you store both

03 Reranking

Retrieve broad (20–50), score carefully on a shortlist (5–10). Saves LLM context for the best chunks.

Cross-encoder / API rerank

Model scores (query, doc) pairs. Highest quality; extra latency/cost. Cohere / Jina / local cross-encoder.

Light heuristics

Boost title matches, exact token hits, recency. Cheap first step before a paid reranker.

hybrid retrieve 30→ rerank→ top 8 → RAG budget
Security
Rerank after RBAC filter — never fetch candidates without workspace_id + role filter first.

    06 Implement in this project

    Minimal path — keep one public search method, add hybrid + optional rerank behind it.

    1. Keep the facade

      Callers stay on WorkspaceVectorSearch.search(...). Add flags/settings, don’t fork routes.

    2. Add sparse index

      Options: Qdrant sparse vectors on chunk text, or Postgres tsvector on note/file text. Prefer Qdrant if you want one filter path (reuse build_rbac_filter).

    3. Fuse candidates

      # inside wrapper.search (sketch)
dense = await dense_query(..., limit=overfetch)
sparse = await sparse_query(..., limit=overfetch)
merged = rrf_fuse(dense, sparse, k=60)
# still RBAC-filtered — never merge unfiltered lists

    4. Optional rerank

      New ai/retrieval/rerank.py: take list[SearchResult] + query → reordered list. Call only when RERANK_ENABLED. Start with title/exact-token boost; later Cohere/Jina.

    5. Config (append-only)

      HYBRID_SEARCH_ENABLED: bool = False
HYBRID_OVERFETCH: int = 30
RERANK_ENABLED: bool = False
RERANK_TOP_N: int = 8

    6. Validate

      Use GET /ai/test-search with exact-ID queries + paraphrases. Compare dense-only vs hybrid. Trace retrieval span: log chunks_retrieved + mode.

    07 Checklist

    • Dense ≠ sparse — know when each fails
    • Hybrid = retrieve both → fuse (RRF is fine)
    • Rerank = overfetch then score shortlist
    • RBAC filter before any merge/rerank
    • Extend WorkspaceVectorSearch, not routers
    • Gate with /ai/test-search + golden exact-ID cases
