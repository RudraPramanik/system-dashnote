## Context

See proposal.md for why the first L2 paste cannot be compared to the 0.7 floors. This design stays inside the laptop quality CLI (`evals/run_quality.py`, `evals/quality_lab.py`). Collection, tenancy, and the chat path stay as they are. DeepEval 3.9.9 `GEval` uses score range `(0, 10)` when no rubric is passed, then sets `score = g_score / 10`. The three metric step lists currently end with “Return a score from 0 to 1”.

## Goals / Non-Goals

**Goals:**

- One judge-scale fix, one durable record, one style-rubric alignment, then one live re-run of the existing twelve chat goldens.
- Unit tests that lock the scale wording, the style voice, and JSONL-to-markdown rendering without calling a judge or the API.

**Non-Goals:**

- Editing `src/ai/prompts/rag.py` or `src/ai/workflows/workspace_assistant.py`.
- Agent answer goldens, faithfulness, floor changes, golden corpus edits, or CI wiring.
- Suppressing DeepEval’s Rich progress bar. The JSONL is the record; the console may still redraw.

## Decisions

### 1. Delete the 0–1 instruction; do not pass a custom rubric

Remove the step that says to return a score from 0 to 1 from correctness, completeness, and style. Leave `GEval` on its default `(0, 10)` range. Do not pass `rubric=`, which would replace that range.

Alternative considered: multiply reported means by 10 after the fact. That hides the bug and still stores the wrong per-case numbers. Rejected.

Alternative considered: a custom rubric locked to 0–1 with span 1. That fights the library template, which asks for an integer on `score_range`. Rejected.

### 2. The CLI writes JSONL, then renders the markdown report

Each scored row appends one JSON object: `id`, `scores`, `reasons`. Path: `evals/quality_scores.jsonl`, replaced at the start of each run so a second run cannot mix with the first. After scoring, render `evals/eval_report_2.md` from that file (environment, judge model, aggregates, `n`, SKIP reasons, per-case scores and reasons). Print reasons on the console as well; the file remains the source of truth when Rich overwrites the terminal.

`evals/eval_report.md` stays untouched as the historical paste.

### 3. Style rubric matches the answer string the product already emits

Replace `STYLE_RUBRIC` with the declared voice: concise; no invented facts; preserve marker tokens present in the notes; the fixed refusal sentence is the allowed non-answer. Style’s evaluation params stay `ACTUAL_OUTPUT` only. Do not splice `citations` into the judged text.

The product already puts citations on `ChatResult.citations` and grounds them against retrieved chunk ids in `src/ai/services/rag_service.py`. Asking the judge to find citations inside `answer` measures a field the generator is not instructed to fill.

### 4. The article is written from the JSONL after the live run

`evals/article.md` is not generated by the CLI. After `run_quality.py` finishes, write it from `quality_scores.jsonl` / `eval_report_2.md`: what run 1 measured, the scale bug, the declared voice, the run 2 numbers, and what is deferred (prompt edits, agent answers, faithfulness). If collection or the judge fails closed, the article records that outcome and does not invent means.

### 5. Tests stay offline

Extend `tests/evals/test_quality_lab.py` (and a small runner test if the writer lives in `run_quality.py`):

- Built evaluation steps do not contain a 0–1 score instruction.
- `STYLE_RUBRIC` matches the declared voice and does not require citation prose inside the answer.
- A fixture list of scored rows writes JSONL and a markdown report whose aggregates match `aggregate_metric_scores`.

No pytest path calls NIM, Gemini, or `POST /ai/chat`.

### Process ownership

The API and the ARQ worker are unchanged. The laptop operator runs the CLI against Compose. Qdrant collections are not touched. No Alembic, settings, or Compose edits.

## Risks / Trade-offs

- [gpt-oss-20b still scores the answers poorly on a true 0–10 scale] → Record the means and reasons. Do not edit the RAG prompt or lower the floor to force a pass in this change.
- [Rich still garbles the terminal] → Operators read `eval_report_2.md` and the JSONL.
- [Re-seed inserts duplicate marker notes] → Same as the first run. Markers stay unique strings; do not add a cleanup migration.
- [Reasons are long] → Store them in full in JSONL; the markdown may truncate a reason only if the JSONL keeps the full text and the report says so.

## Migration Plan

No serving deploy. Rollback is reverting the CLI and rubric text. The first paste file is not migrated.

## Open Questions

None. Whether run 2 clears 0.7 is an outcome to record, not a decision that changes this design.
