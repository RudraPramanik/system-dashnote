Networking & HTTP

How a request reaches DashNote’s FastAPI app — sockets, DNS, TLS, HTTP semantics, connection reuse, and what Nginx actually does in front of Uvicorn.

Must learn DashNote-mapped FastAPI · NestJS

00 Overview

Every API call is: resolve a name → open a TCP connection → (often) TLS handshake → speak HTTP → reuse or close the connection. Latency lives in each hop — not just “slow code.”

Client→ DNS→ TLS / edge→ Nginx→ Uvicorn :8000→ FastAPI

DashNote today: Client → Nginx :80 → api:8000 (Docker DNS). TLS at edge is planned, not shipped.

Transport

TCP reliability vs UDP speed. Connection setup cost dominates short APIs.

Application

HTTP methods, status codes, headers — the contract clients and proxies understand.

Edge

Reverse proxy terminates clients, forwards to apps, adds rate limits and headers.

01 TCP · UDP · DNS · TLS

Pick the right transport, resolve names, then encrypt — before HTTP even starts.

TCP vs UDP

TCPUDP
Guarantee Ordered, reliable streams Datagrams; no delivery guarantee
Cost Handshake + state; higher latency to first byte Near-zero setup; good for realtime / DNS
Use HTTP, databases, most APIs DNS queries, QUIC/HTTP/3 under the hood, games, VoIP
DashNote
All API traffic is TCP. Postgres (asyncpg), Redis, Qdrant, and S3 clients also ride TCP. You almost never choose UDP in this stack — but you do pay TCP handshake cost on cold connections.

DNS

  • Client asks: “what IP is api.example.com?” — cached at OS / recursive resolvers.
  • In Docker Compose, service names (api, db, redis, qdrant) resolve via embedded DNS.
  • Slow or flapping DNS shows up as intermittent connect timeouts — not as FastAPI errors.

Covered

Compose DNS between Nginx → api:8000 and app → db / redis / qdrant.

Should be

Prod public DNS (Cloudflare A/AAAA → VPS), health-aware targets, short TTLs only when you need fast failover.

TLS

  • Encrypts TCP; handshake adds 1–2 RTTs unless session resumed / TLS 1.3 0-RTT.
  • Usually terminates at the edge (Caddy / Cloudflare / LB), not inside each Uvicorn worker.
  • App must trust X-Forwarded-Proto from a known proxy — never from the open internet alone.

Partial

ProxyHeadersMiddleware in src/main.py; HTTPS URLs in prod env examples; MinIO/R2 SSL flags.

Should be

Listen :443 with Caddy/Certbot or Cloudflare Full Strict; tighten trusted_hosts; no plain HTTP to the world.

02 HTTP/1.1 · HTTP/2 · status · headers

HTTP is the shared language between browsers, Nginx, and your handlers.

HTTP/1.1 vs HTTP/2

TopicHTTP/1.1HTTP/2
Multiplexing One request at a time per connection (pipelining rare) Many streams on one TLS connection
Headers Plain text, often repeated HPACK compression
Where it matters Browser ↔ edge; simple proxies Many parallel API calls; gRPC often on h2
DashNote today
Nginx forces proxy_http_version 1.1 to Uvicorn. That is correct for most WSGI/ASGI upstreams. HTTP/2 belongs at the client ↔ edge hop once TLS is live — not required on api:8000 first.

Status codes (practical map)

CodeMeaningDashNote use
200 / 201OK / createdNormal reads & creates
204No bodyDeletes / logout
400Bad inputInvalid AI / agent payloads
401 / 403AuthN / AuthZJWT + permissions
404Missing resourceNotes, files, threads
422ValidationFastAPI / Pydantic default
429Rate limitedNginx + Redis; Retry-After
500UnhandledGlobal handler in main.py
502 / 503Upstream / unavailableEmbedding fail / AI off / health deps

Headers that matter in production

  • Authorization — Bearer JWT (DashNote auth deps)
  • Host, X-Forwarded-For, X-Forwarded-Proto, X-Real-IP — set by Nginx
  • X-Request-ID — Nginx sets it; app should bind it into logs (gap today)
  • SSE: Content-Type: text/event-stream, Cache-Control: no-cache, X-Accel-Buffering: no
  • Retry-After on 429 — tells clients when to retry

03 Keep-alive · timeouts · pools → latency

p99 is often connection setup and wait-in-queue — not CPU. Reuse connections; bound waits.

Keep-alive

Reuse TCP (and TLS) so the next request skips handshake. Nginx upstream: keepalive 32.

Timeouts

Every hop needs a deadline: client, proxy, app outbound (LLM, Qdrant), DB.

Pools

Cap concurrent sockets to DB / Redis / HTTP. Exhausted pool = latency cliff.

How it shows up as latency

SymptomLikely cause
First request slow, next fast Cold TCP/TLS; no keep-alive reuse
Spiky p99 under load Pool wait (DB/HTTP) or thread/worker saturation
Hangs then sudden errors Missing timeout — waits until OS/proxy kills the socket
SSE stalls behind Nginx Proxy buffering; DashNote sets X-Accel-Buffering: no
DashNote map
  • Covered: Nginx upstream keepalive; SQLAlchemy pool_pre_ping; Redis singleton; Qdrant/LLM timeouts; SSE keep-alive headers
  • Should be: Explicit DB pool_size / overflow; Nginx proxy_read_timeout for long SSE; shared httpx client with limits for egress; request deadlines end-to-end

04 Reverse proxy & load balancer

Clients should not talk to app processes directly in production.

What a reverse proxy actually does

  • Accepts client connections (often TLS)
  • Forwards to one or more upstreams (Uvicorn workers / pods)
  • Adds/rewrites headers, rate limits, compression, static files
  • Hides internal ports; can buffer or stream responses

Load balancer vs reverse proxy

Reverse proxy

L7 “front door” for one service: path routing, headers, auth edge, caching.

Load balancer

Spreads traffic across many identical backends (round-robin, least-conn, consistent hash).

Nginx often does both: proxy + (when you add more server lines) load balance.

DashNote Nginx (real config)

nginx/default.conf

upstream api_upstream {
    server api:8000;
    keepalive 32;
}

server {
    listen 80;
    location / {
        limit_req zone=api_per_ip burst=20 nodelay;
        proxy_pass http://api_upstream;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Request-ID $request_id;
    }
}

Covered

  • Single upstream + keepalive pool
  • Per-IP rate limit at edge
  • Forwarded IP / proto / request-id
  • Prod compose: only Nginx publishes :80

Should be

  • TLS :443 (Caddy / Cloudflare)
  • Multiple upstreams when you scale API replicas
  • SSE-aware timeouts / buffering directives
  • Health-checked upstream removal

1. Meaningful status codes + headers

Status & Retry-After 
# FastAPI — mirrors DashNote rate-limit / health style
from fastapi import FastAPI, HTTPException, Response
from fastapi.responses import JSONResponse

app = FastAPI()

@app.get("/notes/{note_id}")
async def get_note(note_id: str):
    note = await repo.get(note_id)
    if note is None:
        raise HTTPException(status_code=404, detail="Note not found")
    return note

@app.get("/health")
async def health(response: Response):
    ok = await db.ping() and await redis.ping()
    if not ok:
        response.status_code = 503
        return {"status": "degraded"}
    return {"status": "ok"}

@app.middleware("http")
async def rate_limit_headers(request, call_next):
    # When limited, return 429 + Retry-After (see core/security/rate_limit.py)
    if await is_limited(request.client.host):
        return JSONResponse(
            status_code=429,
            content={"detail": "Too Many Requests"},
            headers={"Retry-After": "1"},
        )
    return await call_next(request)
// NestJS — same semantics
import {
  Controller, Get, Param, Res, HttpStatus,
  NotFoundException, Injectable, NestMiddleware,
} from '@nestjs/common';
import { Response, Request, NextFunction } from 'express';

@Controller('notes')
export class NotesController {
  @Get(':id')
  async get(@Param('id') id: string) {
    const note = await this.repo.find(id);
    if (!note) throw new NotFoundException('Note not found');
    return note;
  }
}

@Controller('health')
export class HealthController {
  @Get()
  async check(@Res({ passthrough: true }) res: Response) {
    const ok = await this.db.ping() && await this.redis.ping();
    if (!ok) {
      res.status(HttpStatus.SERVICE_UNAVAILABLE);
      return { status: 'degraded' };
    }
    return { status: 'ok' };
  }
}

@Injectable()
export class RateLimitMiddleware implements NestMiddleware {
  async use(req: Request, res: Response, next: NextFunction) {
    if (await isLimited(req.ip)) {
      res.setHeader('Retry-After', '1');
      return res.status(429).json({ detail: 'Too Many Requests' });
    }
    next();
  }
}

2. Outbound HTTP client — timeouts + connection pool

Shared client (reuse TCP) 
# FastAPI / httpx — one client for the process (should-be for DashNote egress)
import httpx
from contextlib import asynccontextmanager
from fastapi import FastAPI

@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.http = httpx.AsyncClient(
        timeout=httpx.Timeout(connect=3.0, read=30.0, write=10.0, pool=5.0),
        limits=httpx.Limits(max_connections=100, max_keepalive_connections=20),
        http2=False,  # match upstream; enable when edge/deps speak h2
    )
    yield
    await app.state.http.aclose()

app = FastAPI(lifespan=lifespan)

@app.get("/proxy-qdrant-health")
async def qdrant_health():
    r = await app.state.http.get("http://qdrant:6333/readyz")
    r.raise_for_status()
    return {"ok": True}
// NestJS — undici/fetch with Agent pool (Node 18+)
import { Injectable, OnModuleDestroy } from '@nestjs/common';
import { Agent, fetch } from 'undici';

@Injectable()
export class HttpEgressService implements OnModuleDestroy {
  private agent = new Agent({
    connections: 20,          // keep-alive pool per origin
    connect: { timeout: 3000 },
    bodyTimeout: 30_000,
    headersTimeout: 10_000,
  });

  get(url: string) {
    return fetch(url, { dispatcher: this.agent });
  }

  async onModuleDestroy() {
    await this.agent.close();
  }
}

// Controller
@Get('proxy-qdrant-health')
async qdrantHealth() {
  const r = await this.http.get('http://qdrant:6333/readyz');
  if (!r.ok) throw new ServiceUnavailableException();
  return { ok: true };
}

3. Trust proxy headers + bind request ID

Proxy headers · request ID 
# FastAPI — DashNote has ProxyHeadersMiddleware; add request-id binding
from contextvars import ContextVar
from uuid import uuid4
from fastapi import FastAPI, Request
from uvicorn.middleware.proxy_headers import ProxyHeadersMiddleware

request_id_ctx: ContextVar[str] = ContextVar("request_id", default="-")
app = FastAPI()

# Prod: set trusted_hosts to your Nginx / Caddy host — not "*"
app.add_middleware(ProxyHeadersMiddleware, trusted_hosts=["nginx", "localhost"])

@app.middleware("http")
async def request_id_middleware(request: Request, call_next):
    rid = request.headers.get("x-request-id") or str(uuid4())
    token = request_id_ctx.set(rid)
    try:
        response = await call_next(request)
        response.headers["X-Request-ID"] = rid
        return response
    finally:
        request_id_ctx.reset(token)
// NestJS — behind Nginx / reverse proxy
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { randomUUID } from 'crypto';
import { Request, Response, NextFunction } from 'express';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // Trust X-Forwarded-* from local proxy only
  app.getHttpAdapter().getInstance().set('trust proxy', 1);

  app.use((req: Request, res: Response, next: NextFunction) => {
    const rid = (req.headers['x-request-id'] as string) || randomUUID();
    (req as any).requestId = rid;
    res.setHeader('X-Request-ID', rid);
    next();
  });

  await app.listen(8000);
}
bootstrap();

4. SSE headers that survive a reverse proxy

Streaming through Nginx 
# FastAPI — matches src/ai_routes/chat.py pattern
from fastapi.responses import StreamingResponse

async def event_gen():
    yield "data: {\"token\": \"hi\"}\n\n"

return StreamingResponse(
    event_gen(),
    media_type="text/event-stream",
    headers={
        "Cache-Control": "no-cache",
        "Connection": "keep-alive",
        "X-Accel-Buffering": "no",  # critical behind Nginx
    },
)
// NestJS — SSE through reverse proxy
import { Controller, Get, Res } from '@nestjs/common';
import { Response } from 'express';

@Controller('ai')
export class ChatController {
  @Get('stream')
  stream(@Res() res: Response) {
    res.setHeader('Content-Type', 'text/event-stream');
    res.setHeader('Cache-Control', 'no-cache');
    res.setHeader('Connection', 'keep-alive');
    res.setHeader('X-Accel-Buffering', 'no');
    res.flushHeaders();

    res.write('data: {"token":"hi"}\\n\\n');
    // ... write more events, then res.end()
  }
}
