Model routing & token economics

Learn how tokens, context budgets, and provider routing shape cost and quality — then apply the same patterns to DashNoteSystem (LiteLLM, hybrid Gemini embeddings + NVIDIA NIM chat) or any AI backend.

01 Why tokens & routing matter

Every LLM call is billed (and latency-bound) by tokens. Routing decides which model pays for which job. Get either wrong and you burn money or quality.

Tokens drive

  • Billable cost (input vs output rates)
  • Latency (more tokens → slower)
  • What fits in context (window limits)
  • What you must truncate (budgets)

Routing drives

  • Which provider / model string
  • Cheap models for tags vs strong for agents
  • Fallback when a provider is down
  • Embedding vs chat separation
DashNote principle
The product owns orchestration and budgets — not inference infra. Swap models via LLM_MODEL / EMBEDDING_MODEL env; keep code on LiteLLM.

02 Tokenization

Models don’t read characters — they read tokens (subword pieces from a tokenizer, often BPE/WordPiece). Pricing and context limits are in tokens, not words.

A token is a discrete ID the model’s vocabulary maps to. Common English: ~3–4 characters per token, ~0.75 words per token. Code, JSON, and non-English can be denser (more tokens per character).

TOKEN_BUDGET_PER_REQUEST = 8000 is a character budget for retrieved context + history packing — a practical proxy, not a true tokenizer count. Chunker token_estimate uses word splits. For billing accuracy, prefer provider usage.prompt_tokens from LiteLLM.

  • Prompt / input: system + history + retrieved context + user message
  • Completion / output: generated answer (often priced higher per 1K tokens)
  • Embeddings: input-only; billed per embedding token or character depending on provider

03 Context windows & budgets

Model context window = max tokens (input + output) the model accepts. App budget = what you choose to send so cost/latency stay sane.

04 Pricing models

Most hosted APIs bill per million tokens (or per 1K). Rates differ for input, output, and embeddings.

Cost ≈ (prompt_tokens × input_price) + (completion_tokens × output_price)

  • Output is often 2–5× input price — long answers are expensive
  • Agent loops multiply cost: each tool round = another completion
  • Cap with AGENT_MAX_ITERATIONS and smaller max_tokens for tools

Embeddings bill on input tokens only. DashNote batches (EMBEDDING_BATCH_SIZE=32) and caches in Redis:

embed:v1:{sha256(text)}  →  skip provider call on hit

Changing EMBEDDING_MODEL or dimension requires full re-index of Qdrant collections.

  • Retries on rate limits (still billed on success; failed attempts may vary by provider)
  • Structured JSON salvage retries
  • Governance LLM calls on destructive actions
  • Streaming vs non-streaming — usually same token bill; latency differs
Observability hook
DashNote already extracts prompt_tokens, completion_tokens, total_tokens, and cost (when LiteLLM sets _hidden_params.response_cost) into the Langfuse llm_generation span.

06 Caching & savings levers

The cheapest token is the one you never send.

Already in DashNote

  • Redis embedding cache (EMBEDDING_CACHE_*)
  • Char budget + history trim
  • Low max_tokens for tags/metadata
  • Additive automation skipped for governance LLM

Common next levers

  • Prompt cache / prefix caching (provider-dependent)
  • Route short tasks to cheaper models
  • Lower retrieval limit when scores are high
  • Sample traces for cost dashboards

07 Model routing fundamentals

Routing = choose provider + model (+ optional fallback) per request class.

StrategyIdeaWhen
Static env One LLM_MODEL for all chat DashNote today — simplest
Task routing Different models for tags / RAG / agent Cost optimization without quality loss
Fallback chain NIM → OpenAI → degrade Provider outages / quotas
Quality router Classifier picks cheap vs strong High volume mixed difficulty
Hybrid providers Embeddings ≠ chat provider DashNote: Gemini embed + NIM chat
LiteLLM model string
Format: provider/model-or-path. Examples: gemini/gemini-embedding-2, nvidia_nim/mistralai/mistral-medium-3.5-128b, openai/gpt-4o-mini. Prefix selects the backend; keys come from env via configure_litellm_env().

11 How to implement in this project

Concrete upgrade path from “one LLM_MODEL” to task-aware routing + better token accounting — without breaking import laws.

  1. Inventory call sites

    List every litellm.aembedding / acompletion / acompletion_with_retry / acompletion_structured caller. Tag each: embed | rag | agent | tags | metadata | governance.

  2. Add settings (append-only)

    In src/config.py, keep LLM_MODEL as default, then add optional overrides:

    LLM_MODEL_RAG: str | None = None
LLM_MODEL_AGENT: str | None = None
LLM_MODEL_STRUCTURED: str | None = None  # tags / metadata / governance
# Resolve: specific or fall back to LLM_MODEL

  3. Add a tiny router helper

    New file src/shared/llm/routing.py (allowed imports only):

    def resolve_chat_model(task: Literal["rag","agent","structured"]) -> str:
    s = get_settings()
    if task == "rag":
        return s.LLM_MODEL_RAG or s.LLM_MODEL
    if task == "agent":
        return s.LLM_MODEL_AGENT or s.LLM_MODEL
    return s.LLM_MODEL_STRUCTURED or s.LLM_MODEL

    Wire into RagService, call_model, and structured callers — pass model=resolve_chat_model(...).

  4. Optional fallbacks

    Wrap acompletion_with_retry: on exhausted retries / 503 from primary, try LLM_MODEL_FALLBACK once. Log [LLM_FALLBACK]. Do not silently switch embeddings mid-index.

  5. True token budgets (optional)

    Today: char budget. Next: estimate with LiteLLM token_counter(model, text) (or tiktoken for OpenAI-compatible) inside ContextBuilder. Keep char budget as fallback if counter unavailable.

  6. Cost metrics

    Emit Prometheus counters from tracing layer (not from ai/): dashnote_llm_tokens_total{task,direction}, dashnote_llm_cost_usd_total{task} when response_cost exists. Panel in Grafana next to API Overview.

  7. Validate

    python scripts/test_nvidia_nim.py
$env:PYTHONPATH="src"; python -m ai.services.rag_service
# Change LLM_MODEL_* in .env → rebuild api+worker
docker compose up -d --build api worker
# Confirm Langfuse llm_generation model field + usage

What not to do

  • Don’t import Langfuse or FastAPI into shared/llm
  • Don’t change embedding dim without re-creating Qdrant collections + full re-embed
  • Don’t put workspace_id or model choice from the client body — server decides
  • Don’t remove structured max_tokens caps when adding a “smart” model — cost will explode on tags

Interview one-liners

Budget context aggressively, cap max_tokens by task, cache embeddings, route cheap models to short structured jobs, cap agent iterations, and observe tokens/cost per request in traces.
One completion/embedding API; provider is a model-string prefix + env keys. Switching NIM ↔ OpenAI is config, not a rewrite — critical when you don’t own GPUs.
Embedding dim is a storage contract with the vector DB. Chat models optimize reasoning/tools. Mixing them couples re-index cost to every chat experiment.
