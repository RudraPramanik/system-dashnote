00 How to use this roadmap

Curriculum index for backend + system design. Finish Must, then pull Should topics that match your current product or interview goals. Park Later until the problem appears.

Must learn

Non-negotiable for shipping backends and defending designs in reviews or interviews.

Should learn

What separates solid mid-level from senior — multi-service reality and harder failure modes.

Can learn later

Staff / platform / rare-scale depth. Learn when you need it — don’t block on these first.

Rule of thumb
Finish Must end-to-end → pick 4–6 Should tied to your stack → park Later.

02 Suggested learning order

Build layers bottom-up so design drills have foundations under them.

  1. Foundations

    HTTP · API design · SQL + indexes · auth · caching · config / secrets / env

  2. Async & reliability

    Queues · timeouts/retries · circuit breakers · idempotency · testing basics

  3. Scale patterns

    Load balancing · replicas · sharding intuition · CAP · rate limits

  4. Design drills

    URL shortener · feed · chat · rate limiter · file store — argue tradeoffs out loud

  5. Senior hardening

    Events · sagas/outbox · multi-tenant · SLOs · security · cost · safe migrations

  6. Electives

    K8s deep · multi-region · stream processing · consensus internals

03 Must learn MUST

Core curriculum. If you only finish one tier, finish this — enough to design and operate a solid multi-service backend.

1. Networking & HTTP

backend
  • TCP vs UDP, DNS, TLS, HTTP/1.1 vs HTTP/2, status codes, headers
  • Keep-alive, timeouts, connection pools — how they show up as latency
  • What a reverse proxy / load balancer actually does

2. API design

backendarchitect
  • REST resources, versioning, pagination, filtering, error shapes
  • Idempotency keys, safe vs unsafe methods, webhook delivery
  • When to use sync RPC vs async job + status endpoint

3. Data modeling & SQL

backend
  • Normalization vs denormalization tradeoffs
  • Indexes (B-tree, covering), query plans, N+1
  • Transactions, isolation levels, ACID — when you need them

4. Caching

backend
  • Cache-aside, write-through, TTL, stampede, thundering herd
  • Redis patterns: sessions, rate limits, locks (and their dangers)
  • CDN edge cache vs app cache vs DB buffer pool

5. AuthN & AuthZ

backendarchitect
  • Sessions vs JWT; OAuth2 / OIDC at a practical level
  • RBAC / scopes; service-to-service auth (API keys, mTLS concepts)
  • Tenant isolation as a first-class design constraint

6. Async work & messaging basics

backend
  • Queues vs pub/sub; at-least-once vs exactly-once (practical truth)
  • Workers, dead-letter queues, backoff, poison messages
  • When background jobs beat long HTTP requests

7. Scalability foundations

architect
  • Vertical vs horizontal scale; stateless services
  • Load balancing, read replicas, sharding intuition
  • CAP / PACELC in plain language — pick consistency where it matters

8. Reliability patterns

backendarchitect
  • Timeouts, retries with jitter, circuit breakers, bulkheads
  • Graceful degradation, health checks, readiness vs liveness
  • Idempotent handlers — the #1 distributed-systems habit

9. Observability

backend
  • Structured logs · metrics (RED/USE) · distributed traces
  • SLIs / SLOs / error budgets — design from user experience
  • Dashboards and alerts that page on symptoms, not every spike

10. Storage choices

backendarchitect
  • When SQL vs document vs key-value vs wide-column
  • Object/blob storage for files; signed URLs
  • Hot vs cold data; backup / restore as a design requirement

11. Concurrency & locking

backend
  • Race conditions, optimistic vs pessimistic locking
  • Unique constraints as correctness tools
  • Distributed locks — when to avoid them

12. Database scaling basics

backendarchitect
  • Connection pooling, read replicas, lag
  • Partitioning / sharding keys and hotspots
  • Migrations without downtime (expand → dual-write → contract)

13. Load balancing & edge

architect
  • L4 vs L7; round-robin, least-conn, consistent hashing
  • Sticky sessions (and why to avoid them)
  • CDN for static assets; TLS termination

14. Testing & quality

backend
  • Unit vs integration vs contract vs E2E — what each catches
  • Test doubles for DB / queue / HTTP; migration and idempotency tests
  • Load / soak smoke tests; what you’d assert before shipping a risky change

15. Config, secrets & environments

backend
  • 12-factor config: env vars, secrets vs config, never commit credentials
  • Secret stores / rotation; least privilege for service credentials
  • dev / staging / prod parity; feature flags vs env toggles

16. Classic design drills

architect
  • URL shortener, news feed, chat, rate limiter, file upload / drive
  • Practice: requirements → capacity → API → data → bottlenecks → failure
  • Always state assumptions and what you’d measure in production
Interview + job bar
Clearing Must means you can design a multi-service backend, pick storage/cache/queue tradeoffs, and explain what fails first under load.

04 Should learn SHOULD

Senior depth. Prioritize by what your product already needs — don’t boil the ocean.

1. Consistency, sagas & outbox

architect
  • Distributed transactions reality; saga choreography vs orchestration
  • Transactional outbox / inbox for reliable events
  • Read-your-writes and eventual consistency UX

2. Event-driven architecture

backendarchitect
  • Domain events, event schemas, versioning
  • CQRS when write/read models diverge for real reasons
  • Fan-out for notifications, indexing, analytics

3. Service boundaries

architect
  • Modular monolith vs microservices — cost of the network
  • API gateway / BFF; sync vs async coupling
  • Data ownership: who owns the source of truth

4. Rate limiting & backpressure

backend
  • Token bucket / sliding window; per-user / per-tenant / per-IP
  • Protecting shared dependencies and noisy neighbors
  • Queue depth as a backpressure signal

5. Search systems

backend
  • Inverted index basics; Elasticsearch / OpenSearch intuition
  • Indexing pipeline, freshness vs query latency
  • Relevance tuning at a systems level (not ML research)

6. Multi-tenancy patterns

architect
  • Shared DB + tenant_id vs schema-per-tenant vs silo
  • Row-level security; cross-tenant leak prevention
  • Noisy neighbor: CPU, queue, and connection budgets

7. Security hardening

backend
  • Secrets management, least privilege, dependency risk
  • Threat modeling (STRIDE-lite) for APIs and data flows
  • Injection, SSRF, broken access control — OWASP top risks

8. Delivery & change safety

backend
  • CI/CD, feature flags, canary / blue-green
  • Backward-compatible migrations; expand-contract
  • Rollback plans as part of the design

9. Capacity planning

architect
  • Back-of-envelope: QPS, storage, bandwidth, connections
  • Headroom, peak vs average, growth assumptions
  • Tie estimates to SLOs and the first bottleneck you’d hit

10. Cost & efficiency

backendarchitect
  • Cost drivers: compute, storage, egress, managed services, idle capacity
  • Design tradeoffs that move the bill (cache, batch, compression, region)
  • Unit economics: cost per request / tenant; budgets and alerts

11. Messaging deeper

backend
  • Ordering, partitions, consumer groups
  • Replay, compaction, retention policies
  • When not to use a message bus

12. Realtime & collaboration

backend
  • WebSockets vs SSE vs long polling — pick for the product
  • Presence, fan-out, connection management at scale
  • Conflict awareness (OT/CRDT — concepts, not mastery)

13. Caching & CDN at the edge

architect
  • Cache keys, Vary, purge / soft-purge
  • Origin shield, stale-while-revalidate
  • Geo latency and regional POPs

05 Can learn later LATER

High leverage when you hit the problem; low leverage if you study them all first.

1. Kubernetes & service mesh

backend
  • Scheduling, HPA, network policies, Istio/Linkerd concepts
  • Learn when you own the platform, not on day one of system design

2. Consensus & distributed DBs

architect
  • Raft/Paxos intuition; etcd / ZooKeeper roles
  • Externally consistent stores (Spanner-style) — rare but interview-famous

3. Multi-region & geo

architect
  • Active-active, conflict resolution, latency domains
  • Data residency and failover runbooks

4. Stream processing

backend
  • Kafka deep: partitions, consumer groups, exactly-once claims
  • Flink / Spark streaming for heavy pipelines

5. Data platforms

backend
  • Warehouses, lakehouse, CDC, batch vs streaming ETL
  • Useful for analytics / reporting orgs — not every API team

6. Advanced API styles

backend
  • gRPC streaming, GraphQL federation, AsyncAPI
  • Adopt when the org already standardized on them

7. Database internals

architect
  • WAL, MVCC, vacuum, buffer management
  • Useful for deep performance debugging

8. Chaos & resilience engineering

architect
  • Failure injection, game days, blast-radius control
  • Formal methods — niche staff / platform territory

9. Performance engineering

backend
  • Profiling, flame graphs, GC / allocator effects
  • Tail latency (p99) hunting at scale

10. Networking deep

architect
  • Anycast, BGP basics, DDoS mitigation layers
  • Service discovery, DNS at scale

07 Design drills to practice

Use the same template every time: requirements → constraints → API → data → scale → failure.

Core set (do all)

  • URL shortener
  • Rate limiter
  • News feed / timeline
  • Chat / messaging
  • File upload / Drive-like store

Stretch set

  • Notification system
  • Ticket booking / inventory
  • Search autocomplete
  • Video streaming CDN
  • Distributed job scheduler
Practice habit
For each drill, write down: QPS estimate, storage for 5 years, single points of failure, and the first metric you’d alert on.
