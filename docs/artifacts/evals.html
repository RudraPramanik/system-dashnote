01 Eval-driven development

Change the system only when a metric moves. Prompts, chunk size, and models are hypotheses — goldens are the test suite.

Hypothesis → Change (prompt / model / retrieval) → Run golden + bench → Error analysis → Ship or revert

Do

  • Define pass criteria before changing code
  • Keep a stable golden set (versioned)
  • Compare against last known-good score
  • Promote prod failures → new cases

Don’t

  • “Looks better” vibes-only merges
  • Rewrite goldens to match a worse model
  • Only score final answers (miss retrieval bugs)
  • Skip tenant / RBAC cases

02 Golden dataset

A small, curated, versioned set of inputs + expected signals. Stable enough to gate PRs; rich enough to catch real regressions. 

// retrieval.jsonl
{"id":"r01","query":"When is Q3 launch?",
 "expect_note_id":"…","expect_substring":"Sept 15","k":5}

// rag_answer.jsonl
{"id":"a01","query":"When is Q3 launch?",
 "must_contain":["Sept","15"],"must_not_contain":["2024"],
 "require_citations":true}

// tenant_isolation.jsonl
{"id":"t01","as_role":"member","peer_private_note":"…",
 "query":"secret project X","expect_hits":0}
  • Seed demos — dedicated eval workspace with known notes/files
  • Bug regressions — every fixed failure → one golden
  • Prod mining — thumbs-down / high-latency Langfuse traces
  • Adversarial — empty corpus, cross-tenant, private peer notes
  • Freeze goldens; don’t edit expected text to match a worse model
  • Split golden/ (stable) vs regression/ (recent bugs)
  • Tag cases: retrieval, rag, tenant, agent
  • Target ≥10 cases for v1; ≥5 agent tool scenarios next

05 LLM-as-judge

Use a model to score open-ended quality when exact string match is too brittle — after deterministic checks pass.

Prefer deterministic first

  • must_contain / regex
  • Citation ⊆ retrieved chunk ids
  • JSON schema validity
  • Expected tool name fired

Judge when needed

  • Faithfulness to context
  • Helpfulness / tone
  • Summary completeness
  • Policy / safety nuance
# Judge output — validate with Pydantic (like acompletion_structured)
class JudgeScore(BaseModel):
    faithfulness: int  # 1–5
    grounded: bool
    rationale: str
    pass_: bool = Field(alias="pass")
Calibrate
Spot-check judge vs human on 20–30 cases. If agreement < ~70%, fix the rubric — don’t blindly trust scores. Prefer a different/cheaper model than the system under test when possible.

06 Trajectory evaluation

For agents, the path matters: which tools, in what order, with what args, and whether side effects match the user ask. Final text alone is not enough.

  • Tool selection — expected tool ∈ calls (or exact sequence)
  • Args — required fields present; no fabricated note ids
  • Side effects — DB row created/updated when claimed
  • Budget — steps_taken ≤ AGENT_MAX_ITERATIONS
  • Policy — no mutate unless user asked; tenant fields from state
{"id":"ag02",
 "message":"Save a note titled Launch with body …",
 "expect_tools":["create_note"],
 "forbid_tools":[],
 "expect_side_effect":{"note_title":"Launch"},
 "max_steps":6}
DashNote agent surface
POST /ai/agent → AgentResponse (steps_taken, tool_calls_made). Stream events: tool_start, tool_end. Graph: START → agent → tools → agent → END. Tools: search_notes, create_note, update_note, summarize_workspace.

08 How to implement (this repo)

Concrete path aligned with ship-plan.md and architecture laws in ai.md.

  1. Seed an eval workspace

    Dedicated notes/files with known facts. Never pollute prod user data. JWT role fixtures for member vs admin isolation cases.

  2. Add evals/golden/*.jsonl (≥10)

    Retrieval + RAG + tenant first. Keep agent trajectories as a second file once chat goldens are green.

  3. Write evals/run_eval.py

    # Outline
# 1. Auth → token for eval workspace
# 2. For each retrieval case: GET /ai/test-search → score recall@k
# 3. For each rag case: POST /ai/chat → must_contain + citations ⊆ chunks
# 4. For each tenant case: assert empty / no peer private
# 5. Print PASS n/N + list failures; exit 1 on fail
# Optional: --json for CI artifact; --mock using fixtures/

  4. Wire deterministic checks before judges

    Reuse citation grounding already in product design. Add LLM-as-judge only for faithfulness on a subset; call via acompletion_structured.

  5. Agent trajectory harness

    Drive POST /ai/agent; assert tool_calls_made and DB side effects via notes API. Cap steps with AGENT_MAX_ITERATIONS.

  6. CI gate

    PR job runs golden set against Compose (or fixtures). Intentionally break RBAC once to prove the gate fails. Log runs in EXPERIMENTS.md.

Don’t
Call Qdrant from the eval script for assertions that belong in the API · trust model-supplied workspace_id · put Langfuse SDK in src/ai/* · let judges override deterministic citation failures.

09 Checklist

  • Eval-driven loop: change → measure → ship/revert
  • Golden JSONL for retrieval, RAG, tenant (≥10)
  • Benchmarks: recall@k / MRR / pass rate logged
  • Error buckets used when debugging failures
  • Deterministic checks before LLM-as-judge
  • Agent trajectory cases (≥5) with side-effect checks
  • run_eval.py prints PASS n/N; CI can fail the PR
  • Langfuse used for analysis, goldens for gates
