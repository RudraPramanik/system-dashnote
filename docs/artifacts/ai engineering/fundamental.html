LLM fundamentals

Models, tokens, inference, context, and sampling — the vocabulary you need before prompts, RAG, or agents. Grounded in how DashNote calls models via LiteLLM today.

LiteLLM ✓ temp=0 ✓ retries ✓ tiktoken ✗ routing ✗ reasoning model ✗

01 What is an LLM

A Large Language Model predicts the next token given previous tokens. Everything else — chat, tools, RAG — is orchestration around that loop.

prompt tokens→ model→ next-token probs→ sample→ repeat

What it is

  • Neural net trained on huge text corpora
  • Autoregressive generation (usually)
  • No built-in “truth” — only likelihood

What it isn’t

  • A database (needs RAG for your notes)
  • Always up to date (knowledge cutoff)
  • Deterministic unless you force it
DashNote
Completions: litellm.acompletion via shared/llm/retry.py and RagService. Embeddings are a different model family (gemini/gemini-embedding-2) — still “LLM stack,” not the chat LLM.

02 Foundation models

A foundation model is a general pretrained base (and often its chat-tuned variants) that you adapt with prompts, RAG, fine-tunes, or tools — rather than training from scratch.

StageWhat you get
PretrainNext-token skill on internet-scale text
SFT / InstructFollows chat / instruction format
RLHF / preferenceAligned style, safety, helpfulness
Your appSystem prompts, RAG, tools, evals
Practical note
In product talk, “foundation model” ≈ the vendor model you pick (LLM_MODEL=…). You almost never train one; you compose around it.

03 Proprietary models API via LiteLLM

Closed weights: you call an API; you don’t download the parameters. Strong quality / tooling; weaker on data residency and cost control at scale.

Examples

GPT-4.x, Claude, Gemini, proprietary NIM-hosted SKUs

Pros

Best-in-class, managed infra, frequent upgrades

Cons

Vendor lock, pricing, data leaves your VPC unless contracted

DashNote
Default chat: nvidia_nim/mistralai/mistral-medium-3.5-128b (hosted via NVIDIA NIM). Embeddings: Gemini API. Keys: NVIDIA_NIM_API_KEY, GEMINI_API_KEY, optional OpenAI. LiteLLM prefix selects the provider — swap models without rewriting call sites.

04 Open-weight models not self-hosted

Weights are downloadable (Llama, Mistral, Qwen, …). You can self-host, fine-tune, or run on your GPU — license still matters (“open weight” ≠ always OSI open source).

When to use

  • Data must stay on-prem
  • High volume → unit economics
  • Custom fine-tunes

When not

  • No GPU / ops capacity
  • Need frontier quality tomorrow
  • Team can’t own inference SLOs
DashNote gap
No local vLLM/Ollama path yet. Adding one = new LiteLLM model string + deployment, not a rewrite of RagService / agent — by design.

05 Reasoning models not selected

Models trained to spend tokens on internal “thinking” (o-series, DeepSeek-R1-style, Gemini thinking modes). Better at hard multi-step problems; slower and costlier.

UseSkip
Planning, math, multi-hop agent goalsSimple RAG Q&A, tagging, classification
When latency budget allowsSSE chat where users expect snappy replies
DashNote fit
Today: general chat model at temperature=0. A reasoning SKU is a good optional upgrade for the agent path only — keep RAG on a fast model.

06 Small models not routed

SLMs (≈1–10B, or distilled) for classification, routing, rewriting, tagging — save the big model for hard generation.

user→ small router→ big LLM / RAG / agent
DashNote today
Automation uses the same LLM_MODEL with smaller LLM_STRUCTURED_MAX_TOKENS_* caps — not a separate small model yet. High-ROI next step: route tags/metadata/intent to a cheap model.

07 Inference via API

Inference = running the trained model to produce outputs. Training is rare for app teams; inference is the daily cost and latency surface.

  • Batch — full answer when done (JSON chat)
  • Streaming — tokens as they’re generated (SSE)
  • Embedding inference — vectors, no “chat” sampling
  • TTFT — time to first token (streaming UX)
  • Tok/s — generation speed
  • E2E latency — retrieve + generate (RAG)
  • $ / 1M tokens — input vs output priced differently

acompletion_with_retry · acompletion_structured · embedding provider with tenacity.

Retries: LLM_MAX_RETRIES=4, backoff 2–60s. Exhausted → agent returns 503.

Soft AI boot: missing keys / Qdrant → core API still up; /ai/* degrades.

08 Tokens

A token is the atomic unit the model reads and writes — often a subword piece, not a full word. Billing and context limits are in tokens.

Rough English rule

~4 characters ≈ 1 token · ~100 tokens ≈ 75 words (very approximate).

Why it matters

Prompt + completion must fit the context window. Output capped by max_tokens.

DashNote nuance
TOKEN_BUDGET_PER_REQUEST=8000 is a character budget for retrieved context + history — not a true tokenizer count. Good enough early; inaccurate for multilingual or code-heavy notes.

09 Tokenization no real tokenizer

Tokenization maps text ↔ token IDs with a model-specific vocabulary (BPE, SentencePiece, …). Never assume two models share the same tokenizer.

Real tokenizers merge common pieces (ing, Q3) differently per model.

10 Context window budgeted in app

The context window is the max tokens the model can attend to in one call (system + history + retrieved docs + generation room).

system+ history+ RAG chunks+ completion ≤ window

11 Long context

Huge windows (100k–1M+) let you stuff more — but cost, latency, and “lost in the middle” quality often make RAG + budget better than dumping everything.

Long context wins

  • Whole-file analysis
  • Short multi-doc compare

RAG still wins

  • Large workspaces
  • Cost-sensitive Q&A
  • Citations to specific chunks
DashNote
Default NIM model advertises a large window (…-128b naming), but the app deliberately budgets ~8k chars of context. Don’t remove that without measuring quality + $.

12 Knowledge cutoff

Training data has an end date. The model won’t know events after that unless you supply them (RAG, tools, browsing).

Why DashNote has RAG
Workspace notes and files are private and fresh — outside any foundation model’s training set. Cutoff is why RagService exists; the LLM alone cannot answer “what did we decide in note X?”

Quick check

13 Temperature 0.0

Temperature scales the logits before sampling. Low → peaked distribution (deterministic). High → flatter (creative, unstable).

0 sharp1.5 flat

Toy softmax over fixed logits — illustrates sharpness only.

DashNote
LLM_TEMPERATURE=0.0 for RAG, agent, and automation — prefer reproducible answers and stable JSON. Raise only for brainstorming features if you add them.

14 Parameters

Two meanings — don’t confuse them.

Parameters (weights): billions of learned numbers (7B, 70B, …). More params ≠ always better for your task; cost and latency scale up.

  • temperature, top_p, top_k
  • max_tokens / max_completion_tokens
  • presence_penalty / frequency_penalty
  • stop sequences, seed (when supported)
LLM_MODEL=nvidia_nim/mistralai/mistral-medium-3.5-128b
LLM_TEMPERATURE=0.0
LLM_MAX_TOKENS=2048
LLM_MAX_RETRIES=4
LLM_STRUCTURED_MAX_TOKENS_TAGS=256
LLM_STRUCTURED_MAX_TOKENS_METADATA=512
TOKEN_BUDGET_PER_REQUEST=8000

Not exposed yet: top_p, seed, per-route model overrides.

15 Sampling temp only

After the model outputs a probability distribution over the vocab, sampling picks the next token.

StrategyIdeaDashNote
GreedyAlways argmax (≈ temp 0)Default behavior
TemperatureSoften / sharpen probs0.0
Top-p (nucleus)Sample from smallest set with mass ≥ pProvider default
Top-kOnly from k likeliestNot set
Structured output
For tags/metadata JSON, low temp + schema validation (acompletion_structured) matters more than fancy sampling.

17 Implement in DashNote

Practical upgrades — fundamentals → production knobs. Keep LiteLLM as the boundary.

  1. True token budgeting

    Add tiktoken / provider count API. Replace char heuristic in ContextBuilder with token estimates per model. Setting: TOKENIZER_NAME or derive from LLM_MODEL.

  2. Per-route model + sampling profiles

    LLM_MODEL_RAG, LLM_MODEL_AGENT, LLM_MODEL_AUTOMATION (or a small map). Keep automation on cheap/fast; agent optional reasoning SKU; RAG stays snappy. Expose top_p only where needed.

  3. Intent → small model router

    Classify: answer via RAG vs agent vs “refuse”. Use a small/cheap completion for tags already capped at 256 tokens — swap model string first.

  4. Cutoff honesty in prompts

    One line in RAG system prompt: answer only from provided notes; say when context is missing. Complements retrieval (see llm_prompt.html).

  5. Optional local open-weight

    Compose service: Ollama/vLLM → LiteLLM ollama/… or OpenAI-compatible base URL. Same acompletion_* call sites. Document GPU requirements in Compose profile.

  6. Observability on fundamentals

    Log prompt_tokens / completion_tokens / cost (already partially in LiteLLM hidden params). Dashboard: $/request, TTFT for stream, truncation rate when budget clips.
