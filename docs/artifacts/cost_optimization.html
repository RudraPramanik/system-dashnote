01 Prompt caching partial in DashNote

Don’t pay full price for tokens you send every time. Cache at the provider (prefix reuse) and at the app (embeddings / answers).

Provider prompt cache

  • Stable system + tool schemas as a long prefix
  • Provider stores KV for that prefix
  • Cached input tokens billed at a discount
  • Needs identical prefix bytes (order matters)

App-level caches

  • Embedding cache by text hash
  • RAG answer cache (invalidate on writes)
  • HTTP / Redis cache-aside for reads
  • Skip the LLM entirely on hit
System + tools (stable) + User / RAG context (varies) → Cache hit on prefix → Pay mainly for new tokens
  • Put static instructions first; put dynamic RAG chunks last
  • Don’t permute tool JSON field order across calls
  • Watch provider min token thresholds for cache eligibility
  • Trace cached_tokens in usage when the API exposes it
  • done Embedding Redis: embed:v1:{sha256(text)} — ai/services/cache.py
  • done Notes/notebooks cache-aside + generation invalidation
  • todo Provider prompt-cache flags via LiteLLM
  • todo RAG response cache rag:{wid}:{hash}:{gen} (Slice 11)

02 Token pricing budgeted · cost view TBD

Cost ≈ (input_tokens × $/1M_in) + (output_tokens × $/1M_out) − cache discounts. Cap both sides: context budget and max_tokens.

KnobEffectDashNote
Input context Dominates RAG cost TOKEN_BUDGET_PER_REQUEST=8000 chars
Output cap Stops runaway completions LLM_MAX_TOKENS=2048
Structured jobs Tiny outputs = cheap Tags 256 · metadata 512
Embeddings Paid per embed call Cache hit = $0 for that chunk
Visibility Know $/request Langfuse cost column (ship-plan Day 13)
Rule of thumb
Prefer cutting input (retrieval budget, history limit) before switching models. Agent with many tool rounds multiplies both input and output.

03 Throughput batch + workers

Throughput = useful work per minute under provider TPM/RPM caps. Batch embeddings, bound concurrency, avoid serializing what can pipeline.

Batch

EMBEDDING_BATCH_SIZE=32 — fewer round trips per note.

Parallel workers

ARQ fan-out; scale workers when embed/tag backlog grows.

Bound loops

AGENT_MAX_ITERATIONS=10 caps tool-round cost & latency.

    if kind == "classify":
        return settings.LLM_MODEL_SMALL
    if kind == "structured":
        return settings.LLM_MODEL_STRUCTURED or settings.LLM_MODEL
    return settings.LLM_MODEL  # rag + agent default

05 Rate limits done (API)

Two layers: protect your API from abuse, and respect provider RPM/TPM so retries don’t amplify spend.

App limits (shipped)

  • Nginx: ~10 r/s burst 20
  • FastAPI Redis: 100/min global
  • Login: 5/min
  • 429 + Retry-After; fail-open if Redis unset

Provider limits

  • RPM / TPM tiers
  • Align worker concurrency
  • Backoff on 429 (see Retries)
  • Separate keys/projects per env
# core/security/rate_limit.py
RateLimiter(scope="global", limit=100, window_seconds=60)
RateLimiter(scope="auth_login", limit=5, window_seconds=60)
# key: rate_limit:{scope}:{user_id|ip}:{window}
Cost angle
Rate limits stop runaway clients from burning LLM budget. They don’t replace TOKEN_BUDGET or model choice — they bound request count.

06 Retries done (7.5)

Retry transient failures; never retry auth/bad-request. Unbounded retries = duplicate spend and thundering herds.

ExceptionActionDashNote
RateLimitError, Timeout, ServiceUnavailable, APIConnection Retry with exponential backoff RETRYABLE_EXCEPTIONS
AuthenticationError, BadRequest, NotFound Fail fast FATAL_EXCEPTIONS
LLM_MAX_RETRIES=4 wait 2s → 60s agent → 503 when exhausted worker re-raise → ARQ retry

07 Idempotency done (core paths)

Retries and ARQ redelivery must not create duplicate vectors, tags, or charges for the same logical work.

What DashNote does

  • Deterministic chunk_id (uuid5) → Qdrant upsert
  • Delete-then-upsert per note/file on re-index
  • Embedding cache: same text → same vector, no re-bill
  • Event bus never raises; tasks are re-runnable

Why it saves money

  • Failed job retry ≠ double embed all chunks
  • Cache hits skip provider on unchanged text
  • Upsert avoids orphan duplicate points
  • Safe retries enable aggressive resilience
ai/embeddings/chunker.py — deterministic IDs. Indexers upsert by point id. Rule: always upsert, never blind insert (blueprint critical rules).
Agent create_note is not automatically idempotent across identical user messages — trajectory evals + UX (“already created”) matter. Prefer client idempotency keys for paid write APIs later.

09 How to implement next

Prioritized work that compounds savings without breaking architecture laws.

  1. Measure baseline (Day 13)

    20× /ai/chat + 20× /ai/agent in Langfuse. Record p50/p95 and avg $/req in README or evals/README.md.

  2. Keep winning on input size

    Tune TOKEN_BUDGET_PER_REQUEST and retrieval limit against evals. History: AI_THREAD_MESSAGE_LIMIT. Prefer chat over agent when no tools needed.

  3. Route structured jobs cheaper

    Add LLM_MODEL_STRUCTURED (append-only settings). Point acompletion_structured at it; leave RAG/agent on LLM_MODEL. Re-run tag/meta fixtures.

  4. RAG answer cache (Slice 11)

    key = f"rag:{workspace_id}:{sha256(q)}:{cache_gen}"
# invalidate via existing notes generation counter on write
# never cache across workspaces; include role if answers differ

  5. Provider prompt caching

    Stabilize system + tool defs; enable provider cache headers/params via LiteLLM where supported; log cached vs billed tokens.

  6. Worker ↔ TPM alignment

    Scale workers only after measuring 429 rates. Embedding batch + cache already reduce embed TPM pressure.

Don’t
Retry fatal auth errors · remove citation grounding to “save tokens” · put cost logic in routers · change embedding dim without re-indexing Qdrant · merge agent into chat “to simplify” (destroys the cheap fast path).

10 Checklist

  • Know provider vs app caching (embed cache ≠ prompt cache)
  • Can estimate $/req from input × output × rates
  • TOKEN_BUDGET + MAX_TOKENS + structured caps understood
  • Throughput: batch embeds, bound agent iterations, scale workers carefully
  • Model routing: env switch today; per-job models next
  • API rate limits + provider TPM awareness
  • Retry only RETRYABLE; agent maps exhaustion → 503
  • Idempotent upserts + embed cache make retries affordable
  • Baseline cost documented from Langfuse
