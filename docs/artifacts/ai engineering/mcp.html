01 What is MCP

MCP is the “USB-C for AI context”: one protocol so hosts don’t reinvent per-tool adapters. It does not replace your LLM or agent loop — it standardizes how external capabilities are discovered and invoked.

Host
AI app
Claude Desktop, IDE, DashNote API
→
Client
1:1 session
JSON-RPC + capabilities
→
Server
Capabilities
Tools · resources · prompts

Solves

  • N×M glue between apps and tools
  • Capability discovery at connect time
  • Clear security boundary per server
  • Composable local + remote backends

Does not replace

  • Your LLM provider (LiteLLM)
  • Agent orchestration (LangGraph)
  • Auth / tenancy (JWT wid)
  • Business services (NoteService)

Mental model
Today DashNote wires tools inside the process (get_note_tools() → LangGraph ToolNode. MCP moves that surface behind a protocol so Cursor, Claude, or DashNote can share the same server.

02 MCP Client

The client lives inside the host. One client per connected server. It speaks JSON-RPC, negotiates capabilities, and routes tool/resource/prompt calls.

1Host decides to attach a server (config / user toggle)
2Client opens transport (stdio or HTTP) and sends initialize
3Server replies with name, version, capabilities
4Client lists tools/resources/prompts; caches schemas
5Host maps tools → LLM function defs; model may call them
6Client forwards tools/call; returns result to host

What the client declares

  • Sampling — allow server to request an LLM completion via the host
  • Roots — filesystem / URI boundaries the server may use
  • Elicitation — server can ask the user for more info
  • Lifecycle: connect, initialize, shutdown
  • Capability negotiation — only use advertised features
  • Request/response + notifications
  • Isolate failures: one bad server ≠ crash the host
  • Pass auth / workspace context as the host defines (headers, env, args)
# Pseudocode — host embeds a client session
session = await ClientSession.connect(transport)
init = await session.initialize()
tools = await session.list_tools()
# Host converts tools → OpenAI-style defs for LiteLLM
result = await session.call_tool("search_notes", {
  "query": "Q3 launch",
  # tenant fields injected by host — never trust model alone
})

03 MCP Server

A focused process that exposes capabilities. It does not own the chat UI or the model — it answers list/get/call requests over the negotiated transport.

Tools

Executable actions. Model-facing. Side effects allowed (create note, update).

Resources

Read-only context (URI → data). Files, note JSON, search hits as documents.

Prompts

Reusable templates / workflows the host can surface to users or inject.

Server responsibilities

  • Advertise capabilities in initialize result
  • Implement */list, */get, tools/call
  • Validate args; return structured errors
  • Enforce its own auth boundary (API keys, workspace tokens)
  • Stay small — one domain per server when possible
Security
Servers are powerful. Treat tool args as untrusted. For DashNote, workspace_id / user_id / role must come from the host’s JWT context, not from model-supplied tool arguments alone. 
# Conceptual FastMCP / mcp Python server shape
@mcp.tool()
async def search_notes(query: str) -> str:
    """Search workspace notes. Tenant injected by host auth."""
    ...

@mcp.resource("note://{note_id}")
async def note_resource(note_id: str) -> str:
    ...

@mcp.prompt()
def rag_grounded() -> str:
    return "Answer ONLY from provided resources..."

04 Primitives & messages

Data layer is JSON-RPC 2.0. Discovery first, then get/call.

PrimitiveListUseDashNote mapping
Tools tools/list tools/call search_notes, create_note, update_note, summarize_workspace
Resources resources/list resources/read Note body, file extracted_text, thread history
Prompts prompts/list prompts/get RAG_SYSTEM_INSTRUCTION, agent system prompt
Host + LLM → tool_calls → MCP Client → tools/call → MCP Server → result → next model turn

05 Transports

Same data layer; different pipes. Pick by where the server runs.

stdio

  • Host spawns local process
  • Great for desktop / CLI / Cursor
  • Env vars for secrets
  • One process per server session

HTTP (streamable / SSE)

  • Remote or containerized servers
  • Fits DashNote Compose / cloud
  • Auth via headers / OAuth
  • Shared multi-tenant service possible

stdio — local MCP server for Cursor/Claude Desktop that calls DashNote HTTP APIs with a user token. No change to production API process.

HTTP — embed an MCP endpoint beside FastAPI (or sidecar) so remote hosts connect without spawning a process. Must inherit JWT / workspace isolation.

Both sides declare features during initialize. Only advertised primitives are legal for the session. Don’t call tools/call if the server never declared tools.

07 How to implement (this repo)

Practical path that preserves coexistence of /ai/chat* and /ai/agent* and reuses existing tool handlers.

  1. Phase A — DashNote as MCP Server (highest leverage)

    Expose the four note tools (+ optional resources) so Cursor / Claude Desktop can operate on a workspace. Keep business logic in NoteService / RagService. 

    # Suggested layout (append-only — follow rules.md)
src/ai/mcp/
  server.py          # FastMCP / mcp app entry
  tools.py           # thin wrappers → existing coroutines
  resources.py       # note://  file://  thread://
  auth.py            # map token → workspace_id, user_id, role

# Reuse, don’t rewrite:
ai/tools/note_tools.py   # _search_notes, _create_note, …
ai/tools/schemas.py
notes/service.py
ai/services/rag_service.py

  2. Auth & tenancy

    Accept a DashNote access token (or dedicated MCP PAT). Resolve RequestContext the same way routers do. Inject tenant strings into tool handlers — strip or ignore model-provided workspace_id.

  3. Transport choice

    • stdio first for local Cursor — package as python -m ai.mcp.server
    • HTTP later — mount beside FastAPI or run sidecar in Compose

  4. Phase B — DashNote as MCP Host (optional)

    Add an MCP Client in the agent path so /ai/agent can call external servers (GitHub, calendars, etc.) without forking LangGraph. 

    # Pseudocode in workspace_assistant
builtin = get_note_tools()
external = await mcp_client_tools(settings.MCP_SERVERS)
tools = builtin + external
# ToolNode(tools) — same loop, AGENT_MAX_ITERATIONS still binds

  5. Settings & deps (append-only)

    # config / .env
MCP_ENABLED=false
MCP_SERVER_TRANSPORT=stdio   # or http
MCP_AUTH_REQUIRED=true
# Host mode later:
# MCP_SERVERS=[{"name":"github","url":"..."}]

# requirements — e.g. mcp / fastmcp (pin when you add)

  6. Validate

08 Checklist

  • Host / Client / Server roles clear (1 client per server)
  • Tools vs resources vs prompts distinguished
  • stdio vs HTTP transport tradeoffs known
  • DashNote today = in-process tools; MCP is additive
  • Phase A = MCP Server wrapping NoteService / RagService
  • Tenant IDs from JWT / host auth — never trust model args alone
  • /ai/chat* and /ai/agent* coexistence preserved
  • Qdrant only via WorkspaceVectorSearch / indexers
