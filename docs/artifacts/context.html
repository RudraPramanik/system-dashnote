Context engineering

Selecting, structuring, compacting, and defending the window — the skill that often beats model swaps for RAG and agents in DashNote.

00 Why context wins

Prompt engineering writes instructions. Context engineering decides what else enters the model: history, retrieved notes, tool results, schemas — under a finite budget. Most “mysterious” RAG failures are context problems (see performance.html: lost-in-the-middle, semantic miss).

Prompt engineering

  • System / few-shot wording
  • Tone and rules
  • Output format hints

Context engineering

  • What to retrieve / omit
  • How to order & delimit
  • When to summarize or offload
  • How to fight rot as threads grow
Rule of thumb
Bigger windows do not replace good context. A tight, ranked, well-labeled 4k of evidence often beats a noisy 100k dump.

02 Context compaction summarize missing

Compaction shrinks prior context while preserving decision-critical facts — so new evidence and the current question still fit.

Truncate

Drop oldest turns / lowest-ranked chunks. Cheap; can lose key facts.

Summarize

LLM or extractive summary of old turns → one “memory” message.

Structured digest

Keep bullets: goals, decisions, open questions, IDs — not prose.

# ContextBuilder today (char budget ≈ tokens)
history_budget = TOKEN_BUDGET_PER_REQUEST * 0.7   # 8000 * 0.7
# fit oldest→newest until full; remaining → chunks (min 1)

# Compaction upgrade (sketch)
if history_chars > history_budget:
    summary = await summarize_turns(old_turns)  # structured digest
    fitted_history = [{"role":"system","content": f"THREAD SUMMARY:\n{summary}"},
                      *recent_turns]
Compaction risk
Bad summaries introduce hallucinations into “memory.” Prefer structured fields, cite source message ids, and keep last N raw turns verbatim.

03 Context rot watch chunks_used

Context rot is quality decay as the window fills with noise, contradictions, stale facts, or buried gold — the model still runs; answers get worse.

Symptoms

  • Ignores a chunk that is present
  • Mixes two topics from long history
  • Follows outdated user preference
  • chunks_used ≪ chunks_retrieved
  • Agent loops on old tool spam

Causes

  • Stuffing “just in case”
  • No compaction of long threads
  • Lost-in-the-middle packing
  • Duplicate / near-duplicate chunks
  • Tool results never pruned
Rot typeExampleCountermeasure
Noise rot 20 weak chunks Rerank → top 5
Stale rot Old “deadline Friday” in history Prefer fresh retrieval; timestamp digests
Contradiction rot Two notes disagree Surface conflict; ask user
Position rot Gold in middle of dump Best-first / U-pack
Tool rot Huge tool_end blobs Truncate / summarize tool outputs
Related
Lost-in-the-middle is a special case of position rot — see performance.html. Compaction fights history rot; selection fights retrieval rot.

04 Select · Write · Isolate · Offload

Four complementary moves (beyond compaction) that complete a context-engineering toolkit.

Select

Retrieve / filter only what this turn needs. Hybrid + rerank.

Write

Persist notes, tags, digests outside the window for later select.

Isolate

Sub-agent / tool with narrow context; return a summary to parent.

Offload

Don’t paste the corpus — RAG is external memory. Search again next turn.

Select: Qdrant + RBAC + budget fit. Write: notes/files/tags/threads in Postgres. Isolate: not yet (single agent); research sub-agent would return a brief. Offload: don’t dump whole notebooks into the prompt — search_notes each need.
Short “working memory” block the agent updates (plans, constraints). Keep tiny; rewrite each turn; don’t let it become a second rotting history.

05 Structure & order CHUNK tags

How you delimit and place content changes whether the model treats text as data, instruction, or noise.

DashNote packing

system
… history …
user:
  CONTEXT FROM YOUR NOTES:
  [CHUNK:uuid] (from: Title)
  …

  QUESTION: …

Good habits

  • Question near the end (recency)
  • Best chunks first (or U-pack)
  • Clear section headers
  • Stable IDs for citations
  • Never mix instructions into chunk text unlabeled
Indirect injection
Retrieved notes are untrusted data. Structure helps, but policy + tool gates still required — security.html.

08 How to implement in DashNote

Ordered upgrades that deepen context engineering without breaking Slice laws.

  1. Instrument rot signals (P0)

    # Already logged: history_messages_used, context_chunks_used, budget
# Add to Langfuse / metrics:
chunks_retrieved - chunks_used   # starvation or over-retrieve
history_chars / budget           # history pressure
# Alert when history > 60% and chunks_used == 1

  2. Selection quality before more budget (P0)

    Hybrid + rerank → top 5 (search_ranking.html). Raising TOKEN_BUDGET without selection often increases rot.

  3. Best-first packing (P0)

    # Before ContextBuilder chunk fit:
chunks = sorted(retrieved, key=lambda c: -c["score"])[:8]
# Optional U-pack after taking top 5 (performance.html)

  4. Thread summarization / compaction (P1)

    # ai/memory/compaction.py
async def compact_history(messages: list[dict]) -> list[dict]:
    if estimate(messages) < threshold:
        return messages
    old, recent = messages[:-6], messages[-6:]
    digest = await acompletion_structured(..., schema=ThreadDigest)
    return [{"role":"system","content": format_digest(digest)}, *recent]

# Call from ContextBuilder or ThreadService.load_history

  5. Dedupe retrieved chunks (P1)

    Skip chunks with high Jaccard / embedding similarity to ones already fitted. Reduces noise rot from overlapping note sections.

  6. Agent tool-result compaction (P1)

    # After tool_end, store truncated text in messages
# e.g. keep first 1500 chars + "…[truncated]"
# Or summarize long search_notes returns before re-entering graph

  7. Tokenizer-aware budget (P2)

    Replace char counts with tiktoken / provider token estimate when multi-lingual notes make char≈token unreliable.

  8. Validate

    python -m pytest tests/ai/ -q  # + ContextBuilder unit cases
# Unit: history 10k chars → still ≥1 chunk if retrieved
# Unit: summarization keeps last 6 turns raw
# Manual long thread: answer still cites fresh retrieval
# Compare chunks_used before/after rerank
Don’t
Paste entire notebooks into the system prompt · raise budget to “fix” bad retrieval · summarize without keeping recent raw turns · let tool dumps dominate agent state · treat retrieved text as trusted instructions · starve retrieval below the 30% reserve.

09 Checklist

  • Context engineering ≠ only prompt wording
  • Layers: system · history · retrieval · question · tools
  • Compaction: truncate / summarize / structured digest
  • Rot: noise, stale, contradiction, position, tool
  • Select · write · isolate · offload toolkit clear
  • DashNote: ContextBuilder 70/30 done; summarize/rerank todo
  • Next: instrument → select/pack → compact history → tool trim
