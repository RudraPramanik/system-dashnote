LLM performance & failure modes

Determinism, non-determinism, semantic failure, and lost-in-the-middle — the four ideas that explain many “mysterious” RAG and agent bugs in DashNote.

Determinism Non-determinism Semantic failure Lost in the middle

00 Mysterious failures

When an LLM “randomly” fails, it is rarely random magic. Usually one of: sampling variance, wrong retrieval, correct retrieval the model ignores, or context packed so the answer sits in a blind spot.

Looks like a bug

  • Same question, different answer tomorrow
  • Eval flake on CI
  • “It was in the context!”
  • Agent picks wrong tool once in ten

Often really is

  • Non-determinism (temp / provider)
  • Semantic miss (wrong chunks)
  • Lost in the middle (order / length)
  • Brittle prompt + sampling
Symptom → Same inputs? → Chunks correct? → Position / budget? → Root cause
Performance here ≠ only latency
In this guide, “performance” means reliable task quality: stable answers, grounded RAG, usable evals — not just p95 ms (see cost / latency companions).

01 Determinism temp 0.0

Determinism means the same inputs produce the same outputs. For LLM products you care about two layers: pipeline determinism (chunk IDs, caches) and generation determinism (sampling).

Pipeline (hard)

  • Same note → same chunk_id (uuid5)
  • Same embed text → Redis cache hit
  • Same JWT → same RBAC filter
  • Idempotent Qdrant upsert

Generation (soft)

  • temperature=0 → greedy-ish
  • Optional seed (provider-dependent)
  • Structured JSON schema
  • Still not bit-identical across vendors
# DashNote — generation lean toward determinism
LLM_TEMPERATURE = 0.0          # config.py default
# RagService / agent: temperature=settings.LLM_TEMPERATURE

# DashNote — pipeline is already deterministic
chunk_id = uuid5(NAMESPACE_URL, f"{note_id}:{index}")
embed cache key = sha256(text)
  • Golden evals / CI gates
  • Structured extraction (tags, metadata, governance JSON)
  • Debugging: “did the prompt change or the model?”
  • User expectation of stable Q&A on notes

temperature=0 is not a guarantee of identical strings across providers, model versions, or even consecutive days on the same API. Treat it as “minimize sampling noise,” not “pure function.”

Chat, agent, and structured LLM paths default to 0.0. Chunker + embed cache give reproducible indexing. Generation still needs judge/eval tolerance for wording drift.

02 Non-determinism managed

Non-determinism is useful for creative work and harmful for brittle tool choice / evals. Sources: sampling, floating-point, batching, provider routing, prompt/context drift, and retrieval score ties.

SourceSymptomMitigation
Temperature / top_p Wording & tool choice vary Keep RAG/agent at 0; raise only for creative drafts
Provider routing Sudden quality cliff Pin model id; log model in traces
Context drift History / chunks differ Log chunks_used, thread limit, budget
Retrieval ties Top-k order flips Stable sort by (score, chunk_id)
Agent loop Different tool trajectories Trajectory evals; step budget; lower temp
Eval design
Don’t assert exact string equality on free-form answers. Use semantic judges, citation checks, or structured fields — or run N samples and require pass@k (see evals.html).

03 Semantic failure dense-only RAG

A semantic failure is when the system fails at meaning: retrieval returns the wrong neighbors, the model answers a different question, or embeddings don’t match how users phrase things — even though nothing “crashed.”

Retrieval miss

Right note exists; wrong chunks in top-k (paraphrase, IDs, rare terms).

Grounding miss

Chunks OK; model ignores them or invents beyond context.

Intent miss

Agent answers vs mutates; wrong tool; summarizes instead of quoting.

  • Log top-k titles/scores next to the answer
  • Citation empty while chunks_used > 0 → grounding smell
  • User says “it’s in my notes” → inspect retrieval first
  • Golden: expect_chunk_ids / forbid unsupported claims
  • Hybrid dense + sparse (see search_ranking.html)
  • Rerank shortlist; raise retrieval_limit carefully
  • Chunking: size/overlap; title prepend (already done)
  • Prompt: refuse when context insufficient (RAG rules 1–2)

Dense Gemini embeddings → Qdrant. Default retrieve ~8. ContextBuilder + TOKEN_BUDGET_PER_REQUEST (8000 chars). No hybrid/rerank yet — main semantic upgrade path.

Don’t confuse with lost-in-the-middle
Semantic failure = wrong or unused meaning. Lost-in-the-middle = right evidence present but buried by position/length.

04 Lost in the middle ordering gap

Models attend more to the beginning and end of long contexts. Facts placed in the middle of a long RAG dump are often underused — classic “it was in the prompt!” mystery.

Relative use of evidence by position (schematic U-shape)
1 start
2
3
4 mid
5
6
7 end

Triggers in products

  • Stuffing 20+ chunks “to be safe”
  • Long thread history before evidence
  • Budget keeps low-ranked middle chunks
  • No rerank → score order ≠ utility order

Mitigations

  • Fewer, better chunks (rerank → top 5)
  • Put best evidence first (or question, then gold)
  • “Lost in middle” reorder: best / rest / 2nd-best
  • Reserve budget for context vs history (DashNote ~30%)
# Conceptual: after retrieval + rerank
chunks = rerank(query, retrieved)[:5]
# Optional U-shape packing:
# [best, ...middle..., second_best]  OR simply score-desc (best first)

# DashNote today (ContextBuilder):
# history ≤ 70% budget · remaining → chunks in retrieval order
# build_rag_user_message: CONTEXT block then QUESTION at end

05 More topics

Related failure modes and levers that show up next to the big four.

More chunks / rerank / larger models improve semantic hit rate but hurt p95. DashNote: chat = fast RAG; agent = slower tool loop. Don’t force agent for Q&A.
TOKEN_BUDGET_PER_REQUEST=8000 chars (approx). History can starve chunks — then you get semantic failure that looks like “model dumb.” Log chunks_retrieved vs chunks_used.
Bad splits = semantic failure at source. Title prepend helps. Tune CHUNK_SIZE / CHUNK_OVERLAP; avoid tiny orphan chunks (CHUNK_MIN_LENGTH.
Tags/metadata/governance use acompletion_structured + JSON salvage. Still non-deterministic wording inside fields — validate with Pydantic, not string eq.
LiteLLM routes by prefix (nvidia_nim/…, gemini/…). A silent model swap changes both determinism and semantic behavior — pin versions in settings and record in Langfuse.
Each tool step multiplies variance. Cap AGENT_MAX_ITERATIONS, keep temp 0, eval trajectories — not only final text.

08 How to implement in DashNote

Ordered upgrades that attack mysterious failures without rewriting the stack.

  1. Instrument the mystery (P0)

    Every RAG/agent response already has retrieval counts — surface in Langfuse/logs:

    # Ensure traces include
chunks_retrieved, chunks_used, char_budget,
model id, temperature, top chunk_ids + scores
# When debugging: dump order of chunks in the user message

  2. Stabilize retrieval order (P0)

    # After vector search, before ContextBuilder:
results.sort(key=lambda r: (-r.score, r.chunk_id))
# Prevents tie-flip non-determinism in context packing

  3. Lost-in-the-middle packing (P1)

    # ai/memory/context_builder.py (or rag_service pre-step)
def pack_for_attention(chunks: list[dict]) -> list[dict]:
    if len(chunks) <= 3:
        return chunks  # already score-desc
    best, rest, second = chunks[0], chunks[2:], chunks[1]
    return [best, *rest, second]  # or simply keep top-5 only

# Prefer: rerank → take 5 → best-first (simpler than fancy U-pack)

  4. Reduce semantic miss (P1)

    Implement hybrid dense+sparse + optional rerank (search_ranking.html). Raise quality before raising k.

  5. Eval against the four modes (P1)

    # Goldens
determinism_smoke.jsonl   # same input → structured fields stable @ temp0
semantic_id_lookup.jsonl  # INV-style queries (expect hybrid)
lost_middle.jsonl         # gold fact planted mid-context; expect citation
nondet_agent.jsonl        # trajectory pass@3 for tool choice

  6. Optional seed for CI (P2)

    # settings
LLM_SEED: int | None = None
# litellm.acompletion(..., seed=settings.LLM_SEED)
# Document: not all providers honor seed

  7. Budget guardrails (P2)

    Alert when chunks_used << chunks_retrieved (history starving context). Cap thread messages more aggressively for RAG vs agent.

  8. Validate

    python -m pytest tests/ai/ -q
# Manual A/B: same question ×5 at temp 0 — measure answer variance
# Manual: plant fact in middle of long CONTEXT — does answer cite it?
# Compare chat vs agent latency/quality for the same question
Don’t
Stuff 30 chunks to “fix” retrieval · assert exact free-text in CI · raise temperature to hide flaky tests · blame the model before checking chunks_used and order · replace /ai/chat with agent for every Q.

09 Checklist

  • Pipeline vs generation determinism distinguished
  • Non-determinism sources listed; evals not exact-string by default
  • Semantic failure = miss / grounding / intent — not HTTP 500
  • Lost-in-the-middle: U-shape; prefer fewer better chunks
  • DashNote: temp 0 + chunk uuid5 done; hybrid/rerank/pack todo
  • Debug: same inputs? → chunks? → position/budget?
  • Next: instrument → stable sort → pack/rerank → goldens
