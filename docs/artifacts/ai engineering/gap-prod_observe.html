Prod Observability — Traces · Metrics · CI Evals

LLM products fail silently: 200 OK with wrong answers, slow retrieval, or cost spikes. This guide closes the gap between “we have logs” and production-grade traces, SLIs, lineage, and CI eval gates — mapped to what DashNote already ships.

Langfuse traces Prometheus Grafana CI goldens Quality alerts Lineage

01 Why logs alone aren’t enough

Classic APIs fail with status codes. LLM systems often return 200 with a fluent wrong answer. JSON logs tell you that a request finished — not which chunk was retrieved, which prompt version ran, or whether quality slid.

Logs catch

  • Exceptions, stack traces, 5xx
  • Request IDs, route, latency_ms
  • “Something blew up” incidents

Logs miss

  • Empty retrieval + confident answer
  • Wrong tool chosen mid-agent loop
  • Prompt v3 silently worse than v2
  • $/request creeping 3× overnight
SymptomLog line saysYou actually need
Hallucinated date 200 · 1.2s · chat Trace: retrieval chunks + generation I/O
Slow chat latency_ms=4200 Span breakdown: retrieve vs LLM vs tools
Cost spike (often nothing) Token + cost metrics per model / route
Regression after merge Same error rate Offline golden pass rate in CI
Stack model
Treat observability as three layers: infra (Prometheus/Grafana), LLM traces (Langfuse), and quality gates (offline + online evals). DashNote already has layers 1–2 for RAG; layer 3 is the main gap.
JSON logs + Traces + Metrics + Evals / scores → Ship with confidence

02 Trace model SHIPPED · RAG

One user request = one root observation with nested spans. Langfuse-style tracing lets you open a bad answer and see retrieval → context → generation (and later, tools).

request → retrieval → context_building → llm_generation → tools* → response

* tools = agent path; RAG path stops at generation.

DashNote RAG shape today

Root name rag.answer with metadata workspace_id, user_id, role. Child spans from observability.tracing used only in RagService.answer / stream_answer:

SpanOutput fieldsDebug use
retrieval chunks_retrieved, latency_ms Zero chunks → refuse / empty-context path
context_building chunks_used, char_budget, latency_ms Budget starvation vs over-inclusion
llm_generation tokens, cost, latency_ms Provider slow vs prompt bloat
  • get_langfuse_client() — lazy only; never from main.py lifespan
  • Langfuse SDK only in langfuse_client.py and tracing.py
  • RagService imports observability.tracing only (no direct SDK)
  • Missing keys → no-op spans; app still runs
  • rag_trace flushes in finally; never raises into request path
async with rag_trace("rag.answer", metadata={...}) as t:
    async with rag_span(t, "retrieval") as span:
        chunks = await retrieve(...)
        span.update(output={"chunks_retrieved": len(chunks)})
    async with rag_span(t, "context_building") as span:
        ctx = build(chunks, budget=TOKEN_BUDGET)
        span.update(output={"chunks_used": n, "char_budget": budget})
    async with rag_span(t, "llm_generation", as_generation=True) as span:
        out = await llm.complete(...)
        span.update(output={
            "prompt_tokens": ..., "completion_tokens": ...,
            "cost": ...
        })
Partial / next
Agent trajectories need nested tool spans: tool.search_notes, tool.create_note, loop counters, and final side-effect IDs. Without them you cannot replay “why did it call create?” from Langfuse alone.
user → plan → tool × N → generation → assistant

05 Online vs offline · CI goldens GAP

Offline evals are the merge gate. Online evals catch drift in production. Neither replaces traces — they score them.

Offline (CI)

  • Golden JSONL: fixed queries + asserts
  • Deterministic: must_contain, cite ⊆ retrieved
  • Optional LLM-as-judge (slow, flaky → soft gate)
  • Blocks PR if pass rate < baseline

Online (prod)

  • Sample N% of traces
  • Score faithfulness / user thumbs
  • Write Langfuse scores on trace id
  • Alerts on rolling quality drop

Golden dataset in CI

# .github/workflows/evals.yml (sketch)
- name: Golden RAG evals
  run: |
    PYTHONPATH=src python scripts/run_eval.py \
      --suite goldens/rag_answer.jsonl \
      --baseline .eval-baseline.json \
      --fail-under 0.9
  env:
    OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
    # Prefer stub LLM for retrieval-only cases
  • Happy-path grounded answers with known note text
  • Empty retrieval → refuse (no hallucination)
  • Tenant isolation: peer private note must not appear
  • Citation invent: fail if UUID not in retrieved set
  • 1–2 “hard” ambiguous queries for judge sampling

For each case, create a score on the produced trace: name=golden_pass, value=0|1, comment=case_id. That lets you open failing CI cases in the same UI as prod traces.

DashNote status
Manual gates exist (/ai/test-search, agent e2e scripts). Formal golden suite + CI fail-under gate is the primary observability gap next to agent trajectory depth. See also evals.html.

06 Alerting: quality vs infra

Page the on-call for outages. Slack the AI team for quality regressions. Mixing them burns trust and hides the real fire.

SignalTypeExample thresholdWho
5xx rate / API down Infra > 2% for 5m or scrape DOWN On-call · page
HTTP p95 Infra / capacity p95 > 5s on /ai/* On-call · investigate spans
Golden pass rate Quality (CI) < baseline − 5 pts PR author · block merge
Online faithfulness Quality (prod) Rolling 1h mean < 0.8 AI eng · Slack, not page
$ / request Cost > 2× 7d baseline AI eng · review model / cache
chunks_retrieved = 0 spike Quality / data Share of traces > 30% AI eng · index / embed health

Infra outage

  • Prometheus target DOWN
  • 5xx / timeouts
  • Langfuse may be quiet (no traffic)

Quality regression

  • HTTP green, users unhappy
  • Scores / goldens drop
  • Langfuse shows empty retrieval or bad gens
Anti-pattern
Paging on “answer quality score < 4” from an LLM judge. Judges are noisy — use them for Slack digests and CI soft gates, not 3 a.m. pages.

07 Grafana vs Langfuse

Grafana answers “is the API healthy?” Langfuse answers “what did the model do?” Put the right panels in the right tool.

Put in GrafanaPut in Langfuse
Request rate, 5xx, HTTP p95/p99 Trace waterfall, span I/O, generations
Saturation: CPU, Redis, DB if scraped Prompt / model filters, sessions
Blackbox: scrape UP/DOWN Scores, user feedback, datasets
SLO burn charts Side-by-side prompt A/B traces

10 How to implement next

Three concrete slices: CI eval job, Langfuse score linking, and dashboard panels.

  1. CI golden eval job

    Add goldens/rag_answer.jsonl + scripts/run_eval.py that hits retrieval + chat against a seeded workspace. Fail PR if pass rate < baseline. Keep tenant cases mandatory. 

    # exit non-zero on regression
assert pass_rate >= baseline - 0.05
write_report("artifacts/eval-report.json")

  2. Langfuse score linking

    After each eval case (and sampled online judge), attach scores to the trace id: 

    langfuse.score(
  trace_id=tid,
  name="golden_pass",
  value=1.0 if ok else 0.0,
  comment=case_id,
)
# Online: name="faithfulness", value=0..1

  3. Dashboard panels

    Grafana: add handler-scoped p95 for AI routes. Langfuse: saved views + cost-by-model table reviewed weekly (product habit). Optional Prometheus counter: rag_empty_retrieval_total for data-plane alerts.

  4. Agent trajectory depth

    Extend tracing helpers for tool spans under an agent.run root. Record tool name, args hash (not secrets), latency, success, and step index.

  5. Lineage tags

    Stamp prompt_version + model + GIT_SHA on every rag.answer metadata so CI and prod bisect the same way.

Order of impact
Ship CI goldens before fancy online judges. A flaky judge without a deterministic suite creates noise; a small golden set blocks real regressions tomorrow.
