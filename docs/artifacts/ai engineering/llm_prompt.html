LLM fundamentals, prompts & tools

How chat models work, how to prompt them, how to force JSON schemas, and how tool loops run — tied to DashNote’s LiteLLM + LangGraph paths.

01 LLM fundamentals

A chat LLM predicts the next tokens given a message list. Your app owns context, tools, and validation.

system
Behaviour contract (who you are, rules)
user
Question + optional retrieved context
assistant
Answer text and/or tool_calls
tool
Tool result → fed back for next round

You control

  • Messages & system prompt
  • temperature, max_tokens
  • Tools / response schema
  • Retries & fail-safes

Model controls

  • Token probabilities
  • Whether it follows tools
  • Hallucination risk
  • Latency / cost per call

02 Prompt engineering

Prompts are product code. Keep them isolated, short, and testable.

  • Role + constraints first (“ONLY use context”)
  • Refusal path when info is missing
  • Output shape (markdown / JSON fields)
  • Don’t leak system instructions to the user
  • Keep system prompt lean — budget belongs to context

File: ai/prompts/rag.py — only place for RAG prompt strings.

  • RAG_SYSTEM_INSTRUCTION — grounding rules
  • build_rag_user_message() — question + [CHUNK:uuid] blocks
  • Citations grounded server-side against retrieved set

WORKSPACE_ASSISTANT_PROMPT in workspace_assistant.py.

  • Pass frozen workspace_id / user_id / role
  • Search before inventing note IDs
  • Mutate only when user asks

03 Structured outputs

Don’t regex free text. Define a schema, ask for JSON, validate with Pydantic.

Pydantic schema→ LLM JSON→ salvage fences→ model_validate 
class RAGAnswer(BaseModel):
    answer: str
    cited_chunk_ids: list[str] = []

# RagService: response_format=RAGAnswer
# Automation: acompletion_structured(..., schema=TagsSchema)
Use caseMechanismOn failure
RAG chatresponse_format=RAGAnswerRetry / error path in service
Tags / file metadataacompletion_structuredARQ retries job
Governance decisionstructured + salvageFail-safe block
Never trust LLM IDs alone
cited_chunk_ids are filtered against the retrieved set. Hallucinated chunk UUIDs are dropped.
Models often wrap JSON in markdown fences or preambles. extract_json_blob() strips fences / “Here is the JSON” then finds the outermost {…}.
Structured + tool calls want stability. Creative temperature increases invalid JSON and wrong tool args.

04 Function calling

The model returns a tool name + JSON args. Your code executes; the model never touches the DB directly.

user→ agent (LLM+tools)→ tool_calls?→ execute tools→ agent …→ final answer 
{
  "type": "function",
  "function": {
    "name": "create_note",
    "description": "Create a note in the workspace",
    "parameters": { /* JSON Schema from Pydantic args_schema */ }
  }
}

LiteLLM gets OpenAI-style tools=[...] — not LangChain bind_tools().

workspace_assistant.py: START → agent → (tools ↔ agent) → END

  • call_model → acompletion_with_retry(..., tools=)
  • execute_tools → ToolNode + db_session_var
  • should_continue stops at AGENT_MAX_ITERATIONS
  • Tools call services, never repositories from the LLM layer
  • Tenant IDs frozen from JWT — not from model args for scope
  • Destructive automation → AutomationDecisionEngine
  • Exhausted LLM retries → HTTP 503

06 How to integrate (this repo)

Recipes for adding a new prompted / structured / tool feature without breaking laws.

  1. New RAG-style answer

    Add schema + prompt in ai/prompts/. Call from a service with plain workspace_id strings. Use response_format=YourModel or acompletion_structured. Ground any IDs server-side.

  2. New short structured job (tags-like)

    Worker task → acompletion_structured(messages, schema, max_tokens=256). Keep tokens low. No FastAPI imports in worker/AI.

  3. New agent tool

    Add StructuredTool + Pydantic args_schema in ai/tools/. Implement via service layer. Register in get_note_tools(). Graph already loops — no router changes for tool wiring.

  4. Always use shared LLM helpers

    from shared.llm.retry import acompletion_with_retry
from shared.llm.structured import acompletion_structured
# model=settings.LLM_MODEL  (or future resolve_chat_model)

  5. Validate

    python scripts/test_nvidia_nim.py          # chat + structured + tools
python scripts/e2e_agent_test.py           # agent path
# RAG: POST /ai/chat with JWT — check citations ⊆ retrieved
Don’t
Put prompts in routers · call Qdrant from tools · trust model-supplied workspace_id · skip Pydantic on structured paths · let the agent loop forever (use AGENT_MAX_ITERATIONS).

07 Checklist

  • Know system / user / assistant / tool roles
  • Prompts live in ai/prompts/ (or one named constant) — not routers
  • Structured = schema + validate (+ salvage)
  • Citations / IDs grounded server-side
  • Tools = OpenAI defs via LiteLLM; execute in ToolNode/services
  • Chat vs agent coexistence understood
  • Retries via shared/llm; agent → 503 when exhausted
